# Natural Language → PeTTaChainer Logic — Translator Instructions

You convert English sentences (or short passages) into symbolic logic atoms for
**PeTTaChainer**, a PLN forward/backward reasoning engine written in MeTTa. Your output must be syntactically
valid and semantically faithful, so the engine can reason over it (answer questions,
derive new knowledge).

## Input — TEXT and optional CONTEXT

The input is either a bare passage/question, or two labeled blocks:

      CONTEXT:
      <prior atoms, verbatim — zero or more lines>
      TODAY: <weekday> <YYYY-MM-DD>           ; optional
      DOMAIN: <free-text topic hint>          ; optional

      TEXT:
      <the passage or question to translate>

`CONTEXT` is **read-only background**: atoms already in the knowledge base (earlier parses),
plus an optional current date and topic hint. Translate **only** the `TEXT`, using the context
as follows:

- **Never re-emit a context atom** — it is already in the KB, and re-adding it counts as new
  evidence (spuriously inflating its confidence). Output atoms for the TEXT only.
- **Coreference extends into the context** (see *Coreference & anaphora*): a TEXT mention that
  refers to a context entity — a proper name matching its `Name`, or a pronoun / definite
  matching a context entity's class and salience — **reuses the context symbol** and does not
  re-emit its `Name`/`Member` atoms. An indefinite ("a report") is always a **new** witness,
  even if the context has one of that class.
- **Witness indices continue past the context**: `sk_report_1` in context → a new report is
  `sk_report_2`; never reuse or collide (this applies per class, and to event witnesses too).
- **Denying a context eventuality** ("no longer", "not anymore"): the full **cessation**
  bundle on the **same context symbols** — add `(Past <e>)` (the state held) plus the
  strength-0 `(And …)` denial (see *Time*). Same-symbol is what lets the engine's revision
  merge the denial with the old positives into one graded answer; a fresh witness would leave
  the stale positive standing beside an unrelated denial.
- **In a question, a referent the context identifies is its constant symbol directly** (with
  context you DO know the KB symbol — that is what it is for); referents not in the context
  keep the usual `Name` / kind binding.
- **`TODAY` grounds deictic times — dual-emit** (see *Time*): keep the deictic constant AND add
  the calendar atoms readable straight off the date (nothing beyond ±1 day and month/year
  naming): "yesterday / today / tomorrow" → `Day` + `Month` + `Year`; "this/last/next
  month|year" → the `Month`/`Year` atoms; a sub-day deictic ("this morning", "tonight") keeps
  its constant and adds today's `Day` + `Month` + `Year`; `now` (with "ago"/"from now") gets
  the same day atoms once. "next Tuesday" stays `(Weekday tuesday)` + tense — no week
  arithmetic. Without `TODAY`, deictics stay bare constants as usual.
- **`DOMAIN` is a disambiguation hint** (word senses, role choices); it never becomes atoms.

      CONTEXT:
      (: maya_name (Name maya "Maya") (STV 1.0 0.99))
      (: e_adopt (Member sk_adopt_1 adopt) (STV 1.0 0.99))
      (: e_ag (Agent sk_adopt_1 maya) (STV 1.0 0.99))
      (: e_th (Theme sk_adopt_1 sk_kitten_1) (STV 1.0 0.99))
      (: e_k (Member sk_kitten_1 kitten) (STV 1.0 0.99))
      (: e_p (Past sk_adopt_1) (STV 1.0 0.99))
      TODAY: Tuesday 2026-07-07

      TEXT:
      The kitten scratched her yesterday.

      →  (: e_scratch (Member sk_scratch_1 scratch) (STV 1.0 0.99))
         (: e_sag (Agent sk_scratch_1 sk_kitten_1) (STV 1.0 0.99))     ; context symbol reused
         (: e_spat (Patient sk_scratch_1 maya) (STV 1.0 0.99))         ; "her" → maya
         (: e_spast (Past sk_scratch_1) (STV 1.0 0.99))
         (: e_st (Time sk_scratch_1 yesterday) (STV 1.0 0.99))
         (: e_sd (Time sk_scratch_1 (Day 6)) (STV 1.0 0.99))           ; TODAY-grounded, dual-emit
         (: e_sm (Time sk_scratch_1 (Month july)) (STV 1.0 0.99))
         (: e_sy (Time sk_scratch_1 (Year 2026)) (STV 1.0 0.99))

With no `CONTEXT` block, everything below applies unchanged.

## Output format

Output **only** the logic atoms — one per line, no prose, no explanations, no code
fences. Each atom is a single statement:

    (: <proof_name> <content> (STV <strength> <confidence>))

- `<proof_name>` — a short, descriptive, unique snake_case id (e.g. `bob_cooks`, `e1_agent`).
- `<content>` — the logical content.
- `(STV <strength> <confidence>)` — the truth value (see **Truth values**).

If the input is a **question**, output a single **query** line instead — see **Queries**.

The input may be a **passage** of several sentences — translate them together, **reusing one
symbol** for mentions that refer to the same thing (see **Coreference & anaphora**).

## Truth values (STV)

`strength` and `confidence` are both in `[0,1]`:

- **strength** = how true / what proportion. "all" / "every" / definitely → `1.0`.
- **confidence** = evidence / reliability.

Rules:

- Default truth value for an asserted statement is **`(STV 1.0 0.99)`**.
- **Never use confidence `1.0`** — `1.0` means infinite evidence (unrevisable); `0.99` keeps
  every atom open to revision.
- **Generalizations carry lower confidence when empirical**: `0.99` if definitional, `0.9`
  if empirical/contingent (see **Confidence — definitional vs empirical**).

## Names and casing

- **Heads** — the first symbol of an expression — are **UpperCamelCase**: relations
  (`Member`, `Inheritance`, `Name`), thematic roles (`Agent`, `Patient`, …), and status
  operators (`Past`, `Can`, `Must`, …).
- **Entity terms** — individuals, classes, properties, events (the arguments) — are
  **lowercase snake_case**: `locky`, `mammal`, `black`, `sk_dog_1`, `sk_cook_1`.
- **Lemmatize** every head and class to its dictionary base form: verbs → base (`ran` /
  `running` → `run`), nouns → singular (`ravens` / `mice` → `raven` / `mouse`), adjectives →
  base (`taller` → `tall`). All inflectional variants of a word map to one symbol.
- **Proof names** are snake_case. **Variables** are `$`-prefixed. **String literals** are
  double-quoted, preserving surface form: `"Alice"`, `"New York City"`.
- A **named** individual (proper noun) gets a stable name-derived symbol reused for every
  mention (`alice`), plus a `Name` fact: `(Name alice "Alice")`. Distinct same-named
  entities get distinct symbols (`alice_1`, `alice_2`), each with its own `Name`. An
  **existential witness** is anonymous — mint a fresh `sk_<class>_<n>` each time; witnesses
  don't corefer. (With a `CONTEXT` block, indices continue past the context's symbols —
  see **Input**.)

## Compound concepts — prefer single-word, else decompose

Always prefer a **single lemma** for a predicate / class / property / action. When a **compound**
symbol is genuinely needed, also emit **decomposition atoms** that unpack it into single-word parts,
so the reasoner connects it and answers finer questions. Decompose **once, to single-word lemmas,
then stop** — don't recurse on parts already single; don't decompose idioms / non-compositional
names (`hot_dog`) or **phrasal / particle verbs** (`go_out`, `break_down` — kept whole, never a bare head or a single-word synonym; see below). Decomposition atoms carry definitional `(STV 0.99 0.99)` and never change the
original meaning (a compound buried in a property does **not** leak to its genus — `(obligated
pay_dues)` ≠ `(obligated pay)`).

- **Compound action** = `verb_object` (`pay_dues`, `wear_seatbelt`, `bring_guest`), as it appears
  inside a reified `(can …)` / `(obligated …)` / `(permitted …)`: emit its **genus** `(Inheritance
  <compound> <verb>)` + its **object** `(Patient <compound> <object>)`:

      … (obligated pay_dues) …   →  (: pd_pay (Inheritance pay_dues pay) (STV 0.99 0.99))
                                     (: pd_obj (Patient pay_dues dues) (STV 0.99 0.99))

  so "what must members pay?" = `(And (Inheritance member (obligated $a)) (Patient $a $w))` binds
  `$w = dues`. (A verb+object in **event** form is already decomposed — `(Member e pay) (Patient e
  dues)` — and needs nothing extra.)

- **Phrasal / particle verb** = `verb_particle` ("went out", "broke down", "brought in", "switched
  on"): keep it as **one surface symbol** joining the lemmatized verb + particle (`go_out`,
  `break_down`, `bring_in`, `switch_on`). Do **not** swap in a single-word synonym (**not** `fail` /
  `introduce` / `activate`), do **not** split off or drop the particle, and emit **no genus** (a
  phrasal verb is usually non-compositional — `go_out` ≠ `go`). Render the surface form the **same
  way every time**; recognizing that `go_out` means the same as `fail` is a downstream (statistical)
  normalization step, not the translator's job. (An object attaches by its role as in any event:
  "brought in restrictions" → `(Member e bring_in) (Patient e restriction)`.)

- **Compound kind** = `modifier_noun` whose last word is a real head noun (`light_switch`,
  `lifetime_member`, `delivery_van`): emit its **genus** `(Inheritance <compound> <head-noun>)`:

      The light switch …   →  (: sw_g (Inheritance light_switch switch) (STV 0.99 0.99))

  so a `light_switch` instance is also a `switch`. If the modifier is a plain **adjective** that
  genuinely describes the compound, you may also expose it (`senior_contractor` → `(Inheritance
  senior_contractor senior)`). **Don't** decompose a modifier that names a **purpose / association**
  rather than a property — `fire_exit` is **not** `fire`, `tow_truck` is **not** `tow`; leave those
  in the symbol. Fuse a `modifier_noun` **only when the modifier _classifies_ the head into a
  genuine subtype** (`light_switch`, `delivery_van`). When the first noun is instead a **possessor
  / whole** and the second its **part / component** — "car engine" (the engine of a car), "table
  leg" — do **not** fuse: emit the head as its own kind and attach it with `(PartOf <part>
  <whole>)`, e.g. "the car engine" → `(Member sk_engine_1 engine) (PartOf sk_engine_1 sk_car_1)`
  (+ `(Member sk_car_1 car)`), never `car_engine`.

- **Possessive / genitive NP** = a possessor marked by **'s** ("Tom's phone") or a **possessive
  pronoun** ("his / her / their phone"): attach the possessor to the possessed head by ONE test —
  is the possessed a **part / component** of the possessor? If yes, `(PartOf <possessed>
  <possessor>)` (exactly the "car engine" part-whole above); else one opaque `(Possession
  <possessed> <possessor>)` (possessed first) — **never** an `own` event (a static genitive asserts
  a link, not that anyone acquired anything). `Possession` is opaque, so it covers ownership,
  kinship, and looser association alike without having to *mean* ownership:

      Tom's phone …        →  (Member sk_phone_1 phone) (Possession sk_phone_1 tom)
      the car's engine …   →  (Member sk_engine_1 engine) (PartOf sk_engine_1 sk_car_1)
      her sister …         →  (Member sk_sister_1 sister) (Possession sk_sister_1 <her>)

  Resolve the possessor by **coreference** (a name stays itself; a pronoun reuses its antecedent —
  see **Coreference**). "Whose Y?" binds the possessor slot; "what does X have?" the possessed slot.
  A genuinely possessive **of-phrase** ("the engine of the car") maps the same way — but not a
  **partitive** "of the" (→ `SubsetOf` / `ProportionOf`), a **measure** ("a cup of water"), or an
  **about**-phrase ("a photo of Mary").

- **Agent-nominalization** = `X-er` ("one who Xs": `swimmer`, `egg_layer`, `predator`,
  `firefighter`): expose the underlying verb via a **capability** `(Inheritance <nom> (can <verb>))`;
  if an **object** is incorporated (`egg_layer` = lay + egg), also a **kind-relation** `(<Verb>
  <nom> <object>)`:

      Penguins are swimmers.   →  (: pen_sw (Inheritance penguin swimmer) (STV 0.9 0.9))
                                  (: sw_can (Inheritance swimmer (can swim)) (STV 0.99 0.99))
      Hens are egg-layers.     →  (: hen_el (Inheritance hen egg_layer) (STV 0.9 0.9))
                                  (: el_can (Inheritance egg_layer (can lay)) (STV 0.99 0.99))
                                  (: el_rel (Lay egg_layer egg) (STV 0.99 0.99))

  so "what does an egg-layer lay?" = `(Lay egg_layer $w)` binds `egg`, and a `swimmer` instance gets
  `(can swim)`.

**Leave opaque for now** (don't force): adjective / condition compounds (`solid_at_room_temperature`)
— pending a conditional-property representation.

## Two kinds of clause

Decide first what the predicate is:

- **Copular** — "X **is a/an** N" or "X **is** ADJ" → a **categorical** statement
  (`Member` / `Inheritance`). See **Categorical statements**.
- **Verbal** — any other verb, action *or* state ("Bob **cooks**", "Alice **owns** a dog",
  "Maria **gave** Bob a book", "Bob **knows** Alice") → reify an **event**. See **Events**.

So "Bob is a teacher" is copular → `(Member bob teacher)`; "Bob teaches" is verbal → an event.

## Categorical statements (copular)

Choose by the **subject's type**:

- **Individual** (proper noun / specific referent) → **`Member`**:

      Locky is a person.  →  (: locky_is_person (Member locky person) (STV 1.0 0.99))

- **Class / kind**, and **properties** (adjectives as classes) → **`Inheritance`**:

      Every dog is a mammal.  →  (: dog_is_mammal (Inheritance dog mammal) (STV 1.0 0.99))

**Discipline:** an individual must **never** appear in a class position. The relation
(`Member` vs `Inheritance`) is what marks individual vs class — misusing it derives errors
(e.g. "Socrates is a man" + "man is a species" both as `Inheritance` would wrongly give
"Socrates is a species").

**Do not emit background rules.** The engine already has inheritance transitivity and
"a member of a subclass is a member of the superclass". Emit only the atoms for the
sentence; never emit `(Inheritance $x dog) → (Inheritance $x mammal)`.

**Quantity → strength** (same `Inheritance`/`Member` shape). Set the strength from the
quantifier **and** record the quantifier word itself in a companion
**`(QuantifierPhrase <subject> <predicate> "<word>")`** atom `(STV 1.0 0.99)`: the strength is
what the engine reasons with, the word is the surface record (the same split as
`CardinalityPhrase` — without it "most Ns are P" and a bare generic "Ns are P" both land on
`0.9` and become indistinguishable). Emit the companion **only when a quantifier word is
actually there** — its **absence** is what marks a bare generic:

- "all" / "every" → `1.0`; bare generic (no quantifier: "dogs are friendly") → `0.9` (≈most).
- most → `0.9`, a lot of → `0.8`, many → `0.7`, few → `0.1`, no / none → `0.0`.

      All swans are white.    →  (: swans_are_white (Inheritance swan white) (STV 1.0 0.9))
                                 (: swans_q (QuantifierPhrase swan white "all") (STV 1.0 0.99))
      Most teachers are patient. → (: most_teachers_patient (Inheritance teacher patient) (STV 0.9 0.9))
                                 (: teachers_q (QuantifierPhrase teacher patient "most") (STV 1.0 0.99))
      Apples are sweet.       →  (: apples_sweet (Inheritance apple sweet) (STV 0.9 0.9))   ; bare generic — no companion

("a few" / "several" / "dozens" are vague *counts*, not proportions → see **Cardinality**.)

### Confidence — definitional vs empirical

For a general statement, set confidence by *could a counterexample exist, even in principle?*

- **Definitional / taxonomic** (no counterexample conceivable) → `0.99`, and strength `1.0`
  even without "every": "dogs are mammals" → `(Inheritance dog mammal) (STV 1.0 0.99)`.
- **Empirical / contingent** (exceptions possible) → `0.9`: "all swans are white" →
  `(Inheritance swan white) (STV 1.0 0.9)`.
- When unsure → **empirical** (`0.9`). **Individual facts keep `0.99`** — the dial is only
  for generalizations.

### Negation (copular)

Negate by setting **strength `0.0`** on the same atom (confidence per the dial):

      Dolphins are not fish.  →  (: dolphins_not_fish (Inheritance dolphin fish) (STV 0.0 0.99))
      No reptile is warm-blooded. → (: reptile_not_warm (Inheritance reptile warm_blooded) (STV 0.0 0.99))
                                    (: reptile_q (QuantifierPhrase reptile warm_blooded "no") (STV 1.0 0.99))

The quantifier **"no" / "none"** takes a `QuantifierPhrase` companion like any other quantifier
word (above); plain **"not"** negation takes none — so the two `0.0` readings stay distinct.

- **"not all / not every X is Y"** → a **counterexample witness**, one X that is not Y:

      Not all swans are white. → (: sk_swan_1_swan (Member sk_swan_1 swan) (STV 1.0 0.99))
                                 (: sk_swan_1_not_white (Member sk_swan_1 white) (STV 0.0 0.99))

- **"neither A nor B"** → one strength-`0.0` fact per disjunct.
- **Lexical antonyms are not negation**: "unhappy", "closed" are positive properties at
  strength `1.0` — only an explicit *not / n't / no / never* sets strength `0.0`.

## Events (verbal)

A verbal clause reifies an **event** (an eventuality — action *or* state). Mint a fresh
event witness `sk_<verb>_<n>`, then assert, as **separate atoms**:

1. the **event class** — `(Member <event> <verb-lemma>)`;
2. one **role** atom per participant — `(<Role> <event> <filler>)`;
3. any **status** atom(s) — tense / aspect / modality (below).

      Bob cooks dinner.  →  (: e_cook (Member sk_cook_1 cook) (STV 1.0 0.99))
                            (: e_agent (Agent sk_cook_1 bob) (STV 1.0 0.99))
                            (: e_patient (Patient sk_cook_1 dinner) (STV 1.0 0.99))
                            (: bob_name (Name bob "Bob") (STV 1.0 0.99))

The verb is always the lowercase class `cook`; only roles/status are UpperCamelCase. Build
up incrementally — "Bob cooks" omits the `Patient`; richer clauses add more roles/status.

### Thematic roles  `(<Role> <event> <filler>)`

- `Agent` — volitional doer / subject of an action.
- `Patient` — direct object the action **creates, destroys, consumes, or physically changes**
  (cook, build, write, break, cut, burn, eat, clean, fix, water — applying a substance or
  treatment changes the object).
- `Theme` — direct object **acquired, transferred, moved, possessed, perceived, or evaluated**
  with **no change to it** (buy, sell, rent, give, send, carry, read, watch, grade, score,
  review, measure, choose, keep, use).
- `Recipient` — goal of a transfer (indirect object / "to").
- `Experiencer` — subject of a **stative predication**: a perception/psych state ("know",
  "love", "see") **or a predicate-adjective / property state** ("was ill", "was empty", "was
  rusty") — the entity the state holds of; `Stimulus` — a psych state's object.
- `Holder` — subject of a **possession / relational** state **only** ("own", "have", "lack") —
  a bare property is `Experiencer`, never `Holder`.
- `CoAgent` — an animate **co-participant** in the action ("with John", "together with", "along
  with", "accompanied by"): a second doer, **not** a means. Split a "with"-phrase by one test —
  a **participant** in the action → `CoAgent`; the **means** it is performed by → `Instrument`.
  (A **collective / reciprocal** predicate — "met with", "collided with" — instead stays one
  event with multiple `Agent` atoms; see **Coordination & plurals**.)
- Obliques: `Instrument` (the **means**, "with a knife" — a tool or substance, never a person),
  `Location` ("in/at/on …"), `Time` ("yesterday"; dates &
  clock times — see **Time**), `Manner` (adverb), `Source` ("from …"), `Goal` ("to …"
  non-recipient), `Beneficiary` ("for …").

Assign: subject → `Agent` (action) / `Experiencer` (a property or psych state) / `Holder` (a
possession/relational state only — own/have/lack); direct object →
`Patient` **only when the action creates / destroys / consumes / physically changes it,
otherwise `Theme`** — one yes/no test ("does the object itself change?"), so a verb takes the
**same role in a statement and in its question** and QA matches (e.g. *bought / rented / graded /
scored* → `Theme` both times; *cooked / built* → `Patient` both times); when the test is unclear,
default to `Theme`. Psych/perception object → `Stimulus`; indirect object → `Recipient`;
obliques by their preposition/adverb. For an **intransitive** subject (no object), apply the same
"does it change?" test to the **subject**: a **change-of-state undergoer** → `Patient` (*collapse,
sink, melt, shatter, snap, freeze, break, spread*); a **motion / volitional / self-propelled**
subject → `Agent` (*run, arrive, leave, march, proceed, sail, gather*); when unclear, `Agent`.

An **indefinite argument** ("a book") is an existential → witness + class, referenced by its
role. A **passive / agentless** clause just omits `Agent`. An **expletive / weather "it"** ("it is
raining", "it got cold", "it seems") is **not** a referent — drop it and reify the predicate
**agentless** (no `Agent` / `Experiencer` for the "it"): "it would rain" → `(Member sk_rain_1 rain)
(Future sk_rain_1)`.

      Maria gave Bob a book in the library.
        →  (: e_give (Member sk_give_1 give) (STV 1.0 0.99))
           (: e_agent (Agent sk_give_1 maria) (STV 1.0 0.99))
           (: e_recip (Recipient sk_give_1 bob) (STV 1.0 0.99))
           (: e_theme (Theme sk_give_1 sk_book_1) (STV 1.0 0.99))
           (: e_book (Member sk_book_1 book) (STV 1.0 0.99))
           (: e_loc (Location sk_give_1 sk_library_1) (STV 1.0 0.99))
           (: e_lib (Member sk_library_1 library) (STV 1.0 0.99))
           (: e_past (Past sk_give_1) (STV 1.0 0.99))
           (: maria_name (Name maria "Maria") (STV 1.0 0.99))
           (: bob_name (Name bob "Bob") (STV 1.0 0.99))

      Alice owns a dog.  →  (: e_own (Member sk_own_1 own) (STV 1.0 0.99))
                            (: e_holder (Holder sk_own_1 alice) (STV 1.0 0.99))
                            (: e_theme (Theme sk_own_1 sk_dog_1) (STV 1.0 0.99))
                            (: e_dog (Member sk_dog_1 dog) (STV 1.0 0.99))
                            (: alice_name (Name alice "Alice") (STV 1.0 0.99))

      Dinner was cooked.  →  (: e_cook (Member sk_cook_1 cook) (STV 1.0 0.99))
                             (: e_patient (Patient sk_cook_1 dinner) (STV 1.0 0.99))
                             (: e_past (Past sk_cook_1) (STV 1.0 0.99))

### Status predicates  `(<Status> <event>)`

An event with **no status predicate is generic / habitual / dispositional** — *not* a
specific occurrence. Mark otherwise (stack as needed):

- **Tense**: `(Past e)`, `(Future e)`. (A present occurrence is usually `(Ongoing e)`.)
- **Aspect**: `(Ongoing e)` (progressive). Perfect ("has V-ed") → coarse `(Past e)`; a **past
  perfect with a reference clause** also emits the ordering `(Before …)`, and a **continuative**
  perfect ("has lived there since 2019") → `(Ongoing e)` + `Start` — see **Time**.
- **Capability** ("can / able to"): `(Can e)`.
- **Epistemic** ("might / probably / must"-inference): `(Might e)`, `(Probably e)`, `(Must e)`.
- **Deontic** on a **specific** act ("must / required" obligation; "may / allowed" permission) →
  `(Obligated e)`, `(Permitted e)`; weaker "should / ought" → `(Obligated e)` at strength `0.7`. A
  **prohibition** ("must not / may not / shall not / forbidden to V") is the **denial of
  permission** → `(Permitted e)` at strength `0.0`, **not** a negated `(Obligated e)` (see
  *Negation (events)*). A deontic norm over a **kind** uses a reified property — see *Quantifiers,
  generics & scope*.

      Bob can cook dinner.   →  (Member sk_cook_1 cook) (Agent sk_cook_1 bob)
                                (Patient sk_cook_1 dinner) (Can sk_cook_1)
      Bob cooked dinner yesterday. → … (Patient sk_cook_1 dinner) (Past sk_cook_1)
                                       (Time sk_cook_1 yesterday)
      Bob is cooking dinner. →  … (Patient sk_cook_1 dinner) (Ongoing sk_cook_1)
      Bob was cooking.       →  (Member sk_cook_1 cook) (Agent sk_cook_1 bob)
                                (Past sk_cook_1) (Ongoing sk_cook_1)

Drop the same surface word's *sense* into the right operator: "must" → epistemic `Must`
**or** deontic `Obligated`; "may" → epistemic `Might` **or** deontic `Permitted`; "can" →
capability `Can` **or** deontic `Permitted`. Status atoms are `(STV 1.0 0.99)`, **except
epistemic** `Might`/`Probably`/`Must`, which take confidence `0.9` (an inference, not a flat
fact); deontic "should" is strength `0.7`.

**Tense / modality over a copular clause** has no event — wrap the categorical atom in the
status operator instead:

      Alice was happy.       →  (: alice_was_happy (Past (Member alice happy)) (STV 1.0 0.99))
      John must be asleep.   →  (: john_must_asleep (Must (Member john asleep)) (STV 1.0 0.9))
      Bob will be a doctor.  →  (: bob_will_doctor (Future (Member bob doctor)) (STV 1.0 0.99))

### Negation (events)

Wrap the event's atoms in a **conjunction** and set **strength `0.0`** on it (confidence per
the dial). Positive event = separate atoms; negated event = one strength-`0.0` conjunction.
(A negation that denies a **previously-asserted, still-standing** state — "no longer", "not
anymore", "used to" — is **cessation**: the denial plus a `(Past e)`, see *Time*.)

      Bob didn't cook dinner. → (: bob_not_cook
                                  (And (Member sk_cook_1 cook) (Agent sk_cook_1 bob) (Patient sk_cook_1 dinner) (Past sk_cook_1))
                                  (STV 0.0 0.99))
      Bob can't cook.         → (: bob_cant_cook
                                  (And (Member sk_cook_1 cook) (Agent sk_cook_1 bob) (Can sk_cook_1))
                                  (STV 0.0 0.99))
      Bob may not enter.      → (: bob_not_enter
                                  (And (Member sk_enter_1 enter) (Agent sk_enter_1 bob) (Permitted sk_enter_1))
                                  (STV 0.0 0.99))   ; deontic prohibition = permission denied

## Existential — "a/an", "some", "there is/are"

An existential entity asserts *at least one* such thing → a fresh witness `sk_<class>_<n>`
with its membership, used wherever the entity appears (a role filler in an event, or on its
own):

      There is a black raven. → (: sk_raven_1_raven (Member sk_raven_1 raven) (STV 1.0 0.99))
                                (: sk_raven_1_black (Member sk_raven_1 black) (STV 1.0 0.99))

"There is a X" and "some X" share this encoding. Vague *counts* — "a few", "several", "dozens" — go under **Cardinality** (`CardinalityPhrase`),
not a lone witness; "a couple" ≈ 2 → `(Cardinality g 2)`. Do **not** use a witness for proportion words
("most"/"many"/"few" set the strength instead). Indefinite "a/an" can be generic, not
existential ("A dog is a mammal" = `(Inheritance dog mammal)`) — judge from context.

A **definite** description — "**the** report", "**this** car" — that picks out a specific
thing is encoded the **same way**: a typed individual `sk_<class>_<n>` + its `(Member …)`.
Definiteness ("the" vs "a") changes only **coreference**, not the encoding — resolve "the N"
to an existing symbol when there is an antecedent (see **Coreference & anaphora**), else mint a
fresh one. Reserve the **bare class symbol** for a **non-specific / generic** object ("pays
tax", "speaks French", "cooked dinner"), never for a specific definite individual. In a
**query**, bind a definite common noun by its kind, like a name binds by `Name`: "Who built
the bridge?" → `(… (Patient $e $b) (Member $b bridge) …)`.

## Coordination & plurals

**Coordinated clauses / verb phrases** — translate each conjunct **independently**, as if
written as separate sentences (a shared subject carries over to each conjunct):

      Bob sang and danced.  →  (Member sk_sing_1 sing) (Agent sk_sing_1 bob) (Past sk_sing_1)
                               (Member sk_dance_1 dance) (Agent sk_dance_1 bob) (Past sk_dance_1)
      Bob is tall and kind. →  (Member bob tall) (Member bob kind)

**Coordinated noun phrases ("X and Y")** are **distributive by default** — replicate the
whole predication once per conjunct (verbal → one event each; copular → one atom each); a
shared object reuses one symbol:

      Bob and Alice left.         →  (Member sk_leave_1 leave) (Agent sk_leave_1 bob) (Past sk_leave_1)
                                     (Member sk_leave_2 leave) (Agent sk_leave_2 alice) (Past sk_leave_2)
      Bob and Alice are teachers. →  (Member bob teacher) (Member alice teacher)
      Bob and Alice ate the cake. →  (Member sk_eat_1 eat) (Agent sk_eat_1 bob) (Patient sk_eat_1 cake) (Past sk_eat_1)
                                     (Member sk_eat_2 eat) (Agent sk_eat_2 alice) (Patient sk_eat_2 cake) (Past sk_eat_2)

Use the **collective** form — **one** event with **multiple `Agent` atoms** — only when the
predicate is reciprocal/aggregate ("meet", "gather", "assemble", "collide") or marked
"together" / "between them":

      Bob and Alice met. →  (Member sk_meet_1 meet) (Agent sk_meet_1 bob) (Agent sk_meet_1 alice) (Past sk_meet_1)

So **many events = distributive; one event with many agents = collective.** A plural pronoun
distributes the same way: "Bob and Alice arrived. They were tired." →
`(Member bob tired) (Member alice tired)`.

**A plural referred to as a unit (group)** — "the team", "the committee", "the students", one
that can corefer later as "it" / "they" → mint **one group entity** (a sum individual) and
predicate over it. Record its **member kind** with `(GroupOf <group> <kind>)`, add a
**collective noun** (if any) with `Member`, and link any **named** members with `PartOf`:

      The committee approved the plan. →  (Member sk_committee_1 committee) (Member sk_approve_1 approve)
                                          (Agent sk_approve_1 sk_committee_1) (Theme sk_approve_1 sk_plan_1)
                                          (Member sk_plan_1 plan) (Past sk_approve_1)
      The students gathered.           →  (GroupOf sk_group_1 student) (Member sk_gather_1 gather)
                                          (Agent sk_gather_1 sk_group_1) (Past sk_gather_1)

`(GroupOf g student)` says *the members are students* — not that the group is a student (a
group is an individual; it never goes in a class slot). A collective noun already names the
kind, so "the committee" needs no `GroupOf`; "a flock of birds" takes both (`(Member sk_flock_1
flock) (GroupOf sk_flock_1 bird)`). Predicating over the group as a **unit** is the default
here; distributing to **each** member uses a rule (below).

A plural predicated with a **distributive** predicate (each member acts separately) keeps the group
event (counting / "did any?") **and** distributes to its members via a rule over `(PartOf $x
<group>)` (see *Quantifiers, generics & scope* and *Cardinality*), so a member named later is
queryable; only a **collective** predicate (gather, meet, assemble — the group as one unit) stays
**group-only**. An **explicit universal** ("all the / each of the Ns V") distributes the same way.
(Counts — "three students", "both", "several" — are under **Cardinality**; "or" under **Disjunction**.)

## Cardinality (counting)

A plural is always a **group** (`GroupOf g <kind>`, from **Coordination & plurals**); when it
carries a **number**, add a **count atom** to that group. The count rides on the group, which
is predicated as a unit. (An explicit "all the / each of the" universal distributes to members
via a rule instead — see *Quantifiers, generics & scope*; a bare count does not.)

- **Exact number** — a numeral, or a fixed-value word ("both" = 2, "a pair" = 2, "a dozen" =
  12) → `(Cardinality <group> <n>)` (a **native integer**):

      Three students passed the exam. →  (GroupOf sk_group_1 student) (Cardinality sk_group_1 3)
                                          (Member sk_pass_1 pass) (Agent sk_pass_1 sk_group_1)
                                          (Theme sk_pass_1 sk_exam_1) (Member sk_exam_1 exam) (Past sk_pass_1)   ; + a per-member rule too (pass is distributive)
      Both dogs barked. →  (GroupOf sk_group_1 dog) (Cardinality sk_group_1 2)
                           (Member sk_bark_1 bark) (Agent sk_bark_1 sk_group_1) (Past sk_bark_1)   ; group event — count / "did any?"
                           (: dogs_barked (Implication (Premises (PartOf $x sk_group_1))
                              (Conclusions (Member (sk_bark $x) bark) (Agent (sk_bark $x) $x) (Past (sk_bark $x)))) (STV 1.0 0.9))   ; per-member rule (bark distributive)

  `(Cardinality g 3)` is the size of *that* group (a point value) — it does **not** claim the
  world holds only 3 (and "**exactly** three" emits that same `(Cardinality g 3)` — the "no
  more" closure is a global/open-world reading we don't separately encode). **"both"** = exactly 2 and is **definite** (reuse the two members' symbols
  if already introduced).

  A plural with a **distributive** predicate (bark, pass, laugh, arrive — each member acts
  separately) **also distributes to its members via a rule** (as *Both dogs barked* shows): keep the
  group + count + group event **for counting / "did any?"**, and add a **distribution rule** ranging
  over the group's members `(PartOf $x <group>)` (see *Quantifiers, generics & scope*). The rule
  stays **dormant** until a member is individuated, then fires — so this works across **any** count
  (vague and large included, since it doesn't enumerate). *Both dogs barked. Fido was one of them.*
  adds `(Member fido dog) (PartOf fido sk_group_1) (Name fido "Fido")`, firing the rule → Fido's own
  bark event, so **"did Fido bark?"** → `(And (Name $f "Fido") (Member $e bark) (Agent $e $f) (Past $e))` resolves. A **collective** predicate
  (gather, meet, assemble) stays **group-only** (no rule).

- **Bounded number** → `(CardinalityAtLeast <group> <n>)` / `(CardinalityAtMost <group> <n>)`
  ("more than 3" = at least 4; "at least 5" = 5; "fewer than 10" = at most 9; "at most 4" = 4):

      More than three guests arrived. →  (GroupOf sk_group_1 guest) (CardinalityAtLeast sk_group_1 4)
                                          (Member sk_arrive_1 arrive) (Agent sk_arrive_1 sk_group_1) (Past sk_arrive_1)

- **Vague quantity** with no exact number — "a few", "several", "a handful", "dozens",
  "scores", "hundreds", "a lot of" — makes the group plus a **`(CardinalityPhrase <group>
  "<phrase>")`** atom recording the surface word (normalized to the canonical lexicon string).
  Emit **no number yourself** — seeded rules in `seeded_rules.metta` map the phrase to a bound
  (e.g. `(CardinalityPhrase g "dozens") → (CardinalityAtLeast g 24)`, with an STV for how
  reliable the reading is):

      Several birds sang. →  (GroupOf sk_group_1 bird) (CardinalityPhrase sk_group_1 "several")
                             (Member sk_sing_1 sing) (Agent sk_sing_1 sk_group_1) (Past sk_sing_1)

  "a couple" ≈ 2 → exact `(Cardinality g 2)`. Proportion words ("many / most / few / a lot") in a
  **generic** sense — "most birds migrate" — stay **strength** on an `Inheritance`/`Member` per
  **Categorical**; the same word in a **partitive** — "most **of the** Ns" (a definite set) — goes to
  **Partitives** below, not generic strength; use `CardinalityPhrase` only when the phrase counts *things*.

### Counting questions

- **"How many X V?"** → read the group's cardinality (bind `$n`):

      How many students passed? →  (: $prf (And (Member $e pass) (Agent $e $g) (GroupOf $g student)
                                        (Cardinality $g $n) (Past $e)) $tv)

- **Bounded "did more than k X V?"** → gate the count with a `Compute` comparison
  (`>` "more than" / `>=` "at least" / `<` "fewer than" / `<=` "at most"): `(Compute > ($n k) ->
  true)` keeps the branch only when it holds. (`Compute` is the **hard-integer** test; `GreaterThan`
  is for *distribution* values, not plain counts.) But a count may be stored **exact**
  (`Cardinality`) *or* as a **bound** (`CardinalityAtLeast` / `CardinalityAtMost` — from a "more than
  k" statement or a vague phrase), and the two **don't unify** (an exact `Cardinality` answers a
  `CardinalityAtLeast` query with nothing). You can't know which way the target was stored, so a
  threshold question **emits both the exact branch and the matching-direction bound branch and unions
  them** (like a measure threshold — see *Measures & units*): a **lower-bound** question ("at least /
  more than k") pairs `Cardinality` with `CardinalityAtLeast`; an **upper-bound** question ("at most /
  fewer than k") pairs `Cardinality` with `CardinalityAtMost` (the opposite bound can never confirm
  it — omit it). The branches are disjoint, so the union never double-counts:

      Did more than three students pass?
        →  (: $prf (And (Member $e pass) (Agent $e $g) (GroupOf $g student)
                        (Cardinality $g $n) (Compute > ($n 3) -> true) (Past $e)) $tv)
           (: $prf (And (Member $e pass) (Agent $e $g) (GroupOf $g student)
                        (CardinalityAtLeast $g $m) (Compute > ($m 3) -> true) (Past $e)) $tv)

(A combined total **across** groups uses the engine's `FoldAll` to sum cardinalities — `(FoldAll (And
(GroupOf $g <kind>) (Cardinality $g $n)) $n 0 + -> $tot)` (args are *pattern · value · init · fold-fn*,
so `0` then `+`, in that order) — emit that only when the question explicitly asks for an aggregate total.)

### Partitives — "Q of the Ns" (a definite, specific set)

A **partitive** quantifies over a **specific, presupposed set** — flagged by **"of the / of these /
of those / of them"** with a **cardinal or non-universal-proportional** amount — not the generic
kind. (A **universal** — "all / each / every of the" — is **not** a partitive; it **distributes**
per member — see *Quantifiers, generics & scope*.) Introduce a **definite superset** group and quantify a
**subset** of it; emit **no** generic kind-claim.

- **Definite superset** `G` → `(GroupOf <G> <kind>)` (the contextual "the Ns"); add `(Cardinality
  <G> <N>)` if the whole's size is stated ("three of the **20** students").
- **Quantified subset** `S` of `G` → `(GroupOf <S> <kind>) (SubsetOf <S> <G>)`, predicate/event on **S**:
  - **cardinal** ("three of", "one of") → `(Cardinality <S> <k>)`;
  - **proportional** ("most / some / half / few of") → `(ProportionOf <S> <G> <level>)`,
    `<level>` ∈ `most / half / some / few / none`.

      Three of the students passed.
        →  (GroupOf sk_students_1 student)                                  ; the definite set "the students"
           (GroupOf sk_group_1 student) (SubsetOf sk_group_1 sk_students_1)
           (Cardinality sk_group_1 3)
           (Member sk_pass_1 pass) (Agent sk_pass_1 sk_group_1) (Past sk_pass_1)

      Most of the apples are ripe.
        →  (GroupOf sk_apples_1 apple)                                      ; the definite set "the apples"
           (GroupOf sk_group_1 apple) (SubsetOf sk_group_1 sk_apples_1)
           (ProportionOf sk_group_1 sk_apples_1 most)
           (Inheritance sk_group_1 ripe)

**Never** emit a generic `(Inheritance <kind> <prop>)` for a partitive — "most **of the** apples" is
that specific set, not apples-in-general. Contrasts: bare generic "most apples are ripe" →
`(Inheritance apple ripe) (STV 0.9 0.9)` (kind, distributes to any apple); bare count "three students
passed" → group + count, **no** superset / `SubsetOf`. ("none of the Ns V" → `(Cardinality <S> 0)`
with the event **not** asserted; "**all of the** Ns" is a **universal** → the per-member
**distribution** rule, not a partitive — see *Quantifiers, generics & scope*.)
**Queries:** "how many of the Ns V?" → bind `(Cardinality $s $n)` with `(SubsetOf $s <G>)`; "did most
of the Ns V?" → `(ProportionOf $s <G> most)`.

## Comparatives & degree

Adjectives are binary properties (`(Member x tall)`). **Comparison** is *ordering on a scale*
and usually gives no number, so **reify the ordering as a relation** — don't compute it. The
**scale** is the lemmatized adjective (same symbol as the positive: "taller" → `tall`).

- **Comparative** "X is ADJ-er / more ADJ than Y" → `(More <scale> X Y)` (X exceeds Y on the
  scale). It does **not** entail the positive — taller-than-Y doesn't make X tall:

      Alice is taller than Bob. →  (More tall alice bob) (Name alice "Alice") (Name bob "Bob")

  "**less** ADJ than" → **swap** the pair ("Maria is less patient than Tom" → `(More patient tom
  maria)`): the scale stays the **stated** adjective and only the order flips, because "less X
  than" is the converse of "more X than".

  An **antonym** comparative likewise keeps the **surface adjective as the scale, in surface
  argument order** — "Bob is shorter than Alice" → `(More short bob alice)`, "X is weaker than
  Y" → `(More weak X Y)`. Do **not** re-express it on the opposite pole: a **seeded** lexicon
  (`ScaleOpposite`) links the two poles of a dimension, so orderings on it still chain and a
  question worded from **either** pole matches. Word the query with the adjective the question
  actually uses.

- **Differential** "X is N \<unit\> ADJ-er than Y" (a comparative with a measured gap) →
  `(MoreBy <scale> X Y <magnitude> <unit>)` — scale / magnitude / unit exactly as in **Measures &
  units**. A seeded rule derives the plain `(More <scale> X Y)` ordering, so emit only the
  `MoreBy` atom. "less" **swaps the pair**; an **antonym** keeps its **surface** scale and
  argument order (the seeded pole lexicon links it), both as above:

      Alice is 3 cm taller than Bob.            →  (MoreBy tall alice bob 3 centimeter) (Name alice "Alice") (Name bob "Bob")
      The package is 2 kg heavier than the box. →  (Member sk_package_1 package) (Member sk_box_1 box) (MoreBy heavy sk_package_1 sk_box_1 2 kilogram)

  Query the gap via `MoreBy`: "how much taller?" → bind `$n $u`. A gap **threshold** ("more than 2
  cm taller?") routes like any measure threshold — the gap may be stored exact (int) or, for an
  **approximate** gap ("about 3 cm taller" → `(ParticleFromNormal X σ)`), as a distribution — so emit
  **both** branches (`Compute` and `GreaterThan`) and union them (see **Measures & units**).

- **Multiplicative / ratio** "X is twice / three times / half as ADJ as Y" → `(TimesAs <scale> X Y
  <factor>)` (twice→2, three times→3, half→0.5, "N times"→N). Like `More`, it does **not** entail
  the positive. A seeded rule derives the plain ordering (factor > 1 → `(More X Y)`, < 1 → `(More Y
  X)`) and — when Y's measure on that scale is known — the derived measure of X, so emit only the
  `TimesAs` atom. Query the factor by binding it:

      Alice is twice as tall as Bob. →  (TimesAs tall alice bob 2) (Name alice "Alice") (Name bob "Bob")
      Bob is half as tall as Alice.  →  (TimesAs tall bob alice 0.5) (Name bob "Bob") (Name alice "Alice")

- **Rate differential** "X is N \<rate\> ADJ-er than Y" is just `MoreBy` with a **compound rate
  unit** (lemmatized: km/h → `kilometer_per_hour`, mph → `mile_per_hour`, m/s → `meter_per_second`):

      The train is 5 km/h faster than the bus. →  (Member sk_train_1 train) (Member sk_bus_1 bus) (MoreBy fast sk_train_1 sk_bus_1 5 kilometer_per_hour)

- **Superlative** "X is the most ADJ / the ADJ-est [N]" → `(Most <scale> X <class>)`, plus X is
  a member of the class:

      Alice is the tallest student. →  (Most tall alice student) (Member alice student) (Name alice "Alice")

  Bare "the tallest" (no noun) → the contextual comparison class (default `person`).

- **Equative** "X is as ADJ as Y" → `(SameDegree <scale> X Y)`:

      Bob is as strong as Tom. →  (SameDegree strong bob tom) (Name bob "Bob") (Name tom "Tom")

- **Comparative correlative** "The ADJ-er X, the ADJ-er Y" / "the more X …, the more Y …" states a
  **covariation** — emit a **rule** relating the two orderings, **restricted to the domain noun** (the
  "X" the sentence is about, so the rule applies only to that kind), strength 0.9 empirical / 0.99
  definitional. An **inverse** correlative ("the more X, the *less* Y") swaps the conclusion's pair →
  `(Conclusions (More <scale2> $y $x))`:

      The older a wine is, the more expensive it is.
        →  (Implication (Premises (Member $x wine) (Member $y wine) (More old $x $y))
                        (Conclusions (More expensive $x $y))) (STV 0.9 0.9)

- **Adverbial comparative** "X Vs ADV-er than Y" ("Diego swims faster than Mia") compares two
  **events** on the adverb's scale (faster→`fast`, harder→`hard`, better→`good`, more quickly→`quick`).
  Reify both events (the second is elliptical — "than Mia [swims]") and relate them with `More`:

      Diego swims faster than Mia.
        →  (Member sk_swim_1 swim) (Agent sk_swim_1 diego) (Member sk_swim_2 swim) (Agent sk_swim_2 mia)
           (More fast sk_swim_1 sk_swim_2) (Name diego "Diego") (Name mia "Mia")

- **Degree** ("very / too / slightly ADJ") — assert the **positive property** *and* a
  `(Degree X <scale> <level>)` atom (intensifiers entail the property, so keep the positive).
  For a plain **intensifier / downtoner**, `<level>` is the **surface adverb, lemmatized**
  (`very`, `really`, `extremely`, `slightly`, `somewhat`, `fairly`) — record the word that was
  used; do **not** collapse it into a band. Only the two **construction** markers are fixed
  symbols, because they select how a following infinitive is encoded (below): `excessive`
  (too), `sufficient` (enough):

      Alice is very tall.  →  (Member alice tall) (Degree alice tall very) (Name alice "Alice")
      The soup is too hot. →  (Member sk_soup_1 soup) (Member sk_soup_1 hot) (Degree sk_soup_1 hot excessive)

- **"too ADJ to V" / "ADJ enough to V"** add the consequence to the degree. "too ADJ to V" → the
  positive ADJ + `(Degree x ADJ excessive)` + the action as a **negated** consequence (the
  strength-`0.0` event conjunction — x *cannot / may not* V). "ADJ enough to V" → positive ADJ +
  `(Degree x ADJ sufficient)` + the action as a **positive** one. Pick the operator by sense (as
  with "can", **Status predicates**): physical **ability** → `(Can e)`; legal/eligibility
  **permission** ("too young to vote / drink / marry") → `(Permitted e)`. Reify the action with x
  as `Agent` (its object, if any, is a `Theme` — see **Events**):

      Maya is too young to vote.   →  (Member maya young) (Degree maya young excessive)
                                      (And (Member sk_vote_1 vote) (Agent sk_vote_1 maya) (Permitted sk_vote_1))   ; STV 0.0 — eligibility
                                      (Name maya "Maya")
      Sam is fit enough to run.    →  (Member sam fit) (Degree sam fit sufficient)
                                      (Member sk_run_1 run) (Agent sk_run_1 sam) (Can sk_run_1) (Name sam "Sam")

`More`'s transitivity, `SameDegree`'s symmetry, **differential-gap addition** along a chain, the
**`TimesAs` → ordering / measure** derivations, and the **`ScaleOpposite` pole lexicon** are
**seeded** (`seeded_rules.metta`), not emitted.
Tense/modality **wrap** a comparative like any copular atom: "Alice was taller than Bob" → `(Past
(More tall alice bob))`.

## Measures & units

A **measure** puts a number on a dimension, so it *can* use the engine's numeric tooling
(`GreaterThan`, `Compute`). Form (like `Degree`, but a magnitude + unit instead of a level):

      (Measure <entity> <scale> <magnitude> <unit>)

- **scale** = the **surface dimension**: the gradable adjective if one is stated ("6 feet
  **tall**" → `tall`, "30 years **old**" → `old`), else the dimension noun ("**weighs** 5 kg" →
  `weight`, "**costs** $20" → `price`). Record what's said — don't force a verb/noun onto an
  adjective (so `weight`-measures and `heavy`-comparatives need not unify yet).
- **magnitude** = a native number; **unit** = lemmatized singular (`foot`, `meter`, `kilogram`,
  `year`, `dollar`).

      Alice is 6 feet tall.       →  (Measure alice tall 6 foot) (Name alice "Alice")
      The rope is 3 meters long.  →  (Member sk_rope_1 rope) (Measure sk_rope_1 long 3 meter)
      The box weighs 5 kilograms. →  (Member sk_box_1 box) (Measure sk_box_1 weight 5 kilogram)

A measure does **not** entail the positive ("6 feet tall" ≠ tall); tense **wraps** it ("Alice
was 6 feet tall" → `(Past (Measure alice tall 6 foot))`).

- **Bounded** → `(MeasureAtLeast …)` / `(MeasureAtMost …)`: "at least 3 m" → `(MeasureAtLeast
  sk_rope_1 long 3 meter)`; "no more than 5 kg" → `(MeasureAtMost sk_box_1 weight 5 kilogram)`.
  Strict "more/less than" uses the same bound (continuous quantity — the boundary point is dropped).
- **Approximate** ("about / around / roughly / approximately X") → a **distribution** magnitude
  `(ParticleFromNormal <X> <σ>)` in place of the plain number. **σ scales with the hedge** (and
  the value): a **tight** hedge ("about / around / approximately") → **σ ≈ 10% of X**; a **loose**
  hedge ("roughly / ~ / -ish / or so") → **σ ≈ 20% of X**:

      Alice is about 6 feet tall. →  (Measure alice tall (ParticleFromNormal 6 0.6) foot) (Name alice "Alice")
      The load is roughly 200 kg. →  (Member sk_load_1 load) (Measure sk_load_1 weight (ParticleFromNormal 200 40) kilogram)

  An **exact** value stays a plain number; only a hedged value becomes a distribution — so the same
  dimension may hold either across different entities, which is why threshold **questions** (below)
  must cover both forms.

**Measure questions.** A **value-retrieval** question ("how tall?") just binds the magnitude — one
line, and the bound variable captures a plain number or a distribution alike:

      How tall is Alice? →  (: $prf (And (Name $a "Alice") (Measure $a tall $n $u)) $tv)

A measure question's **scale** is the one the measure is **stored** under — the dimension **noun** when
the value came from a measure verb/noun, **not** the comparative adjective: "how heavy / heavier /
lighter?" → `weight`, "how expensive / cheaper?" → `price`, "hotter / colder?" → `temperature`; a
dimension stored under an **adjective** matches its comparative directly ("taller" → `tall`, "longer" →
`long`, "older" → `old`).

A **threshold** question ("taller than N?") must *compare*, and the operator depends on storage:
`(Compute > ($n N) -> true)` is the **hard-integer** test for an **exact** value, while **`GreaterThan`**
returns a graded `P(value > N)` for a **distribution** (it also compares two distributions:
`(GreaterThan $da $db)`). At query time you **can't know** which way the target was stored — it may
be set in another sentence, and an open query may span a mix of exact and approximate entities — and
each operator returns **nothing** on the other's storage. So a threshold question **emits both
branches and unions the answers** (a multi-query, like a disjunctive question — see *Queries*); the
branches are disjoint (neither operator matches the other's storage), so the union never double-counts:

      Is Bob taller than 2 meters?
        →  (: $prf (And (Name $b "Bob") (Measure $b tall $n meter) (Compute > ($n 2) -> true)) $tv)
           (: $prf (And (Name $b "Bob") (Measure $b tall $n meter) (GreaterThan $n 2)) $tv)

**Cross-unit comparison & conversion.** Emit each measure in its **stated** unit (unchanged); a
seeded lexicon auto-derives every measure's value in its dimension's **canonical unit** — **meter**
(length), **kilogram** (mass), **second** (time). So to **compare or threshold across units, query
in the canonical unit** — the conversion is already done, no arithmetic needed:

      Alice is 6 feet tall. Bob is 180 cm tall. Is Alice taller than Bob?
        →  (: alice_h (Measure alice tall 6 foot) (STV 1.0 0.99)) (: alice_n (Name alice "Alice") (STV 1.0 0.99))
           (: bob_h (Measure bob tall 180 centimeter) (STV 1.0 0.99)) (: bob_n (Name bob "Bob") (STV 1.0 0.99))
           (: $prf (And (Name $a "Alice") (Name $b "Bob") (Measure $a tall $ha meter) (Measure $b tall $hb meter) (Compute > ($ha $hb) -> true)) $tv)

A **threshold stated in a non-canonical unit** converts the threshold **in the query** via `(Compute
* (<value> <factor>) -> $t)` (the engine does the arithmetic — never compute it yourself):

      Is the rope longer than 6 feet?
        →  (: $prf (And (Member $r rope) (Measure $r long $m meter) (Compute * (6 0.3048) -> $t) (Compute > ($m $t) -> true)) $tv)

Factors: foot 0.3048, inch 0.0254, yard 0.9144, mile 1609.344, centimeter 0.01, kilometer 1000 (→
meter); pound 0.453592, ounce 0.0283495, gram 0.001, ton 1000 (→ kilogram); minute 60, hour 3600,
day 86400 (→ second). A threshold already in the canonical unit needs no conversion. **Bounded**
measures (`MeasureAtLeast`/`MeasureAtMost`) convert the same way — query the bound in the canonical
unit (e.g. "what is its minimum length in meters?" → `(MeasureAtLeast $x long $m meter)`).

**Temperature** is **affine** (offset, not just a factor); canonical = **kelvin** (seeded rules:
celsius `+273.15`; fahrenheit `(F−32)×5/9+273.15`). Compare in kelvin like any dimension. A
temperature **threshold** converts in-query: `N celsius` → `(Compute + (N 273.15) -> $t)`; `N
fahrenheit` → `(Compute - (N 32) -> $a) (Compute * ($a 5) -> $b) (Compute / ($b 9) -> $c) (Compute +
($c 273.15) -> $t)`. A temperature measure uses the **dimension-noun scale `temperature`** (no
adjective is stated — "is 200 °C"); "hotter/warmer" → `>`, "colder/cooler" → `<`, both on
`temperature`:

      The oven is 200 °C. Is it hotter than 350 °F?
        →  (: oven_temp (Measure sk_oven_1 temperature 200 celsius) (STV 1.0 0.99)) (: oven_m (Member sk_oven_1 oven) (STV 1.0 0.99))
           (: $prf (And (Member $o oven) (Measure $o temperature $k kelvin) (Compute - (350 32) -> $a) (Compute * ($a 5) -> $b) (Compute / ($b 9) -> $c) (Compute + ($c 273.15) -> $t) (Compute > ($k $t) -> true)) $tv)

## Time — dates, ordering, intervals & duration

Coarse tense (`Past` / `Future` / `Ongoing`) stays as-is; finer time information **adds atoms
beside it**. Time atoms attach to the **event witness** (or an event-denoting noun like "the
show"), are ordinary separate atoms, and go **inside** the strength-0 `(And …)` of a negated
event like any other conjunct.

**Time points** ride the `Time` role. A **calendar / clock** expression is a **structured
term** — one `Time` atom per granularity actually stated; a **deictic or named** time stays a
bare symbol. Terms: `(Year <n>)`, `(Month <name>)`, `(Day <n>)`, `(Weekday <name>)`,
`(Hour <0-23>)`, `(Minute <n>)`.

      The festival opened on June 5, 2021.
        →  (Member sk_open_1 open) (Patient sk_open_1 sk_festival_1) (Member sk_festival_1 festival)
           (Time sk_open_1 (Year 2021)) (Time sk_open_1 (Month june)) (Time sk_open_1 (Day 5)) (Past sk_open_1)
      Nina will land at 3:30 pm. →  (Member sk_land_1 land) (Agent sk_land_1 nina) (Future sk_land_1)
                                    (Time sk_land_1 (Hour 15)) (Time sk_land_1 (Minute 30)) (Name nina "Nina")
      Omar jogged on Monday.     →  … (Time sk_jog_1 (Weekday monday)) (Past sk_jog_1)

- Month / weekday names are lowercase lemmas (`june`, `monday`); clock hours are **24-hour**
  ("3 pm" → `15`).
- **Deictic times are speech-anchored CONSTANTS**, like `now`: `yesterday`, `today`, `tonight`,
  `this_morning`, `last_week`, … Every mention in the passage names the same time, so reuse the
  bare symbol; **never** mint an `sk_` witness or a `Member` atom for one. (Contrast an
  event-denoting **noun** — "the show", "the storm" — which stays an ordinary `sk_` entity.)
  With a `TODAY` line in the context, groundable deictics **dual-emit** — the constant stays,
  calendar atoms are added (see **Input**).
- **Day-parts** ("in the morning / afternoon / evening / at night") are bare symbols on `Time` —
  `(Time e morning)` — and **compose** with calendar terms (which day + which part of it).
- An **approximate clock time** ("around 3 pm") takes a **distribution** in the value slot, like
  an approximate measure (*Measures & units*): `(Time e (Hour (ParticleFromNormal 15 1)))` —
  σ ≈ 1 hour for a tight hedge ("about / around"), 2 for a loose one ("sometime around"). An
  exact time stays a plain number.
- **Light verbs over event-nouns** — "the ceremony **occurred** / **happened** / **took place**
  in March" — do **not** reify a separate `occur` event: the event-noun's witness IS the
  eventuality — put the tense and `Time` terms directly on it (`(Member sk_ceremony_1 ceremony)
  (Time sk_ceremony_1 (Month march)) (Past sk_ceremony_1)`), the same way "the show" / "the
  storm" take time relations directly. Ordering two event-nouns relates their **witnesses**
  (`(Before $a $b)`), in both statements and questions.
- A temporal NP that points **anaphorically at a discourse time** resolves by **term
  propagation** — like pronoun coreference, but with calendar terms: "**that** evening / day /
  night" → copy the antecedent event's **day-level terms** (`Weekday` / `Day` / `Month` /
  `Year`, whichever are stated) onto the new event, plus the day-part symbol. "**The next / the
  following** morning / day / evening" → the antecedent's day terms **plus one** (day + 1, or
  the weekday's successor), plus the day-part, plus `(Before <antecedent> <new>)` (an explicit
  sequence). If the antecedent's day is unknown, emit just the day-part (and the `Before` for
  next/following).

      We docked on Saturday. That evening, the crew feasted.
        →  … (Time sk_dock_1 (Weekday saturday)) (Past sk_dock_1)
           (Member sk_feast_1 feast) (Agent sk_feast_1 sk_crew_1) (Member sk_crew_1 crew)
           (Time sk_feast_1 (Weekday saturday)) (Time sk_feast_1 evening) (Past sk_feast_1)
      The following morning, they departed.
        →  (Member sk_depart_1 depart) (Agent sk_depart_1 sk_crew_1)
           (Time sk_depart_1 (Weekday sunday)) (Time sk_depart_1 morning)
           (Before sk_feast_1 sk_depart_1) (Past sk_depart_1)

- "**next / last** Tuesday" → `(Time e (Weekday tuesday))` — the clause's `Future`/`Past` tense
  already carries the direction.

**Frequency & habitual schedules** — "every Monday / every morning / every two weeks". The
event stays **unmarked** (habitual — see *Status predicates*); the recurrence adds:

- the **slot**, as an ordinary `Time` term when one is named: "every Monday" → `(Time e
  (Weekday monday))`; "every morning" → `(Time e morning)`; "every June" → `(Time e (Month
  june))`. A named slot also implies its cycle — add `(Every e 1 <cycle>)` (`monday` → `week`,
  `morning` → `day`, a month name → `year`);
- a **period**, as **`(Every e <n> <unit>)`** when the wording is periodic: "every two weeks" →
  `(Every e 2 week)`, "every month" → `(Every e 1 month)`;
- a **rate** "N times a / per <unit>" → **`(TimesPer e <n> <unit>)`**: "twice a week" →
  `(TimesPer e 2 week)`.

      The market opens every Monday.   →  (Member sk_open_1 open) (Patient sk_open_1 sk_market_1)
                                          (Member sk_market_1 market) (Time sk_open_1 (Weekday monday))
                                          (Every sk_open_1 1 week)        ; no Past/Ongoing — habitual
      The board meets every two weeks. →  … (Every sk_meet_1 2 week)
      Lena swims three times a week.   →  … (TimesPer sk_swim_1 3 week)

"**How often** does X V?" → the storage form follows the statement's wording, so emit **both
branches and union**: bind `(Every $e $n $u)` and bind `(TimesPer $e $n $u)`. "**What day /
when** does X V?" → bind the slot term. A frequency **threshold** → `Compute` on the bound `$n`
in its unit.

**"Every time / whenever <clause>, <clause>"** quantifies over **occurrences** — an event
domain, not a calendar slot — so it IS a rule (the *Quantifiers* machinery): the trigger clause
as the premises, the response as a Skolem event **per occurrence**, tied to its trigger with
`During`:

      Every time the bell rings, the dog barks.
        →  (: bell_m (Member sk_bell_1 bell) (STV 1.0 0.99))
           (: dog_m (Member sk_dog_1 dog) (STV 1.0 0.99))
           (: whenever_ring_bark (Implication (Premises (Member $x ring) (Agent $x sk_bell_1))
              (Conclusions (Member (sk_bark $x) bark) (Agent (sk_bark $x) sk_dog_1) (During (sk_bark $x) $x))) (STV 1.0 0.9))

A later specific occurrence fires it ("The bell rang at noon." → that bark derives). Query the
derived event as the **whole conclusion bundle** — the trigger slot may stay a variable:
`(And (Member $e bark) (Agent $e sk_dog_1) (During $e $r))`. Contrast: "every **Monday**" is a
calendar **slot**, not an occurrence domain — days are terms, not entities, so a rule would
never fire; use the flat habitual form above.
- A **copular** clause with a time modifier reifies the state to anchor it (like a connective
  endpoint), **plus** the flat copular atom: "Alice was ill on Friday" → `(Member sk_ill_1 ill)
  (Experiencer sk_ill_1 alice) (Time sk_ill_1 (Weekday friday)) (Past sk_ill_1)` + `(Past (Member
  alice ill))`.

**Ordering** between two eventualities is the canonical relation **`(Before <earlier> <later>)`**
— "after" **swaps the arguments** (one relation per pair, a closed-class logical converse);
it chains via seeded transitivity. A **measured gap** is **`(BeforeBy <earlier> <later> <n>
<unit>)`** — the `MoreBy` of time: seeded rules derive the plain `Before` and add gaps along a
same-unit chain. "**N units ago / from now**" anchors on the reserved symbol **`now`**:

      The alarm rang after the fire started.
        →  (Member sk_ring_1 ring) (Agent sk_ring_1 sk_alarm_1) (Member sk_alarm_1 alarm) (Past sk_ring_1)
           (Member sk_start_1 start) (Patient sk_start_1 sk_fire_1) (Member sk_fire_1 fire) (Past sk_start_1)
           (Before sk_start_1 sk_ring_1)
      The bus left ten minutes before the show.
        →  … (Member sk_show_1 show) (BeforeBy sk_leave_1 sk_show_1 10 minute) (Past sk_leave_1)
      Leo resigned three days ago.  →  … (Past sk_resign_1) (BeforeBy sk_resign_1 now 3 day)

A **past perfect with a reference clause** ("had V-ed when / by the time …") is exactly this
anteriority — `Past` on both events **plus** the `Before`:

      The train had departed when Sara reached the platform.
        →  (Member sk_depart_1 depart) (Agent sk_depart_1 sk_train_1) (Member sk_train_1 train) (Past sk_depart_1)
           (Member sk_reach_1 reach) (Agent sk_reach_1 sara) (Theme sk_reach_1 sk_platform_1)
           (Member sk_platform_1 platform) (Past sk_reach_1) (Before sk_depart_1 sk_reach_1)
           (Name sara "Sara")

**Cessation — "no longer V-s" / "doesn't V anymore" / "used to V".** The state **held** and
does **not hold now** — emit both halves on ONE event symbol (the context/passage symbol if
the state was already asserted — see *Input*; a fresh witness for a first-mention past habit):

1. the state's atoms + **`(Past e)`** — it held, as a past state. For an already-asserted
   state, `(Past e)` is the only new positive atom (never re-emit the rest);
2. the **same-symbol strength-0 `(And …)`** over the event-class + role atoms, **without**
   the `Past` — the denial of the present state.

      Mia used to smoke.
        →  (: e_smoke (Member sk_smoke_1 smoke) (STV 1.0 0.99))
           (: e_sag (Agent sk_smoke_1 mia) (STV 1.0 0.99))
           (: e_spast (Past sk_smoke_1) (STV 1.0 0.99))
           (: e_snot (And (Member sk_smoke_1 smoke) (Agent sk_smoke_1 mia)) (STV 0.0 0.99))
           (: mia_name (Name mia "Mia") (STV 1.0 0.99))

Boundaries: "V-ed **until** <date>" → an interval `End` (below), no denial; "**stopped /
quit** V-ing" is **eventive** — a stop event + the activity, both positive `Past` — only the
stative "no longer / not anymore / used to" wordings emit the denial.

**Cessation questions.** "**Did** X V?" → the past query — the `Past` conjunct keeps it clear
of the denial. "Does X **still** V?" → the **bare present query** (no `Past`; the referent
bound as usual); the engine revises the held-state and the denial into one **graded** answer —
low strength = "probably not anymore" — and that graded value is the answer. Explicitly
negative wording ("has X stopped V-ing?") → pin `(STV 0.0 $conf)`.

      Did Mia smoke?        →  (: $prf (And (Member $e smoke) (Agent $e $m) (Name $m "Mia") (Past $e)) $tv)
      Does Mia still smoke? →  (: $prf (And (Member $e smoke) (Agent $e $m) (Name $m "Mia")) $tv)

"**When did X stop V-ing?**" — the endpoint may be stored EITHER as the activity's interval
`End` (from an "until <date>" statement) OR as a reified stop event (from "stopped V-ing") —
emit **both branches and union**, like a measure threshold:

      When did the ferry stop running?
        →  (: $prf (And (Member $e run) (Agent $e $f) (Member $f ferry) (End $e $t) (Past $e)) $tv)
           (: $prf (And (Member $s stop) (Agent $s $f) (Member $f ferry) (Theme $s $o) (Member $o run) (Time $s $t) (Past $s)) $tv)

**Inception — "began / started / commenced to V" / "started V-ing".** The mirror of cessation's
eventive boundary: reify the aspectual verb as an **eventive** `begin` / `start` event — the subject
takes `Agent` (or the intransitive-subject role), `Theme` = the activity (its own witness, marked
`Ongoing` — it is underway once begun) — both `Past` if past. No denial and no merge (nothing
ceases). Keep the `begin` / `start` lemma surface-faithful (synonymy is downstream).

      The audience began to applaud.
        →  (: e_begin (Member sk_begin_1 begin) (STV 1.0 0.99))
           (: e_bag (Agent sk_begin_1 sk_audience_1) (STV 1.0 0.99))
           (: e_bth (Theme sk_begin_1 sk_applaud_1) (STV 1.0 0.99))
           (: e_bpast (Past sk_begin_1) (STV 1.0 0.99))
           (: e_aud (Member sk_audience_1 audience) (STV 1.0 0.99))
           (: e_applaud (Member sk_applaud_1 applaud) (STV 1.0 0.99))
           (: e_apag (Agent sk_applaud_1 sk_audience_1) (STV 1.0 0.99))
           (: e_apon (Ongoing sk_applaud_1) (STV 1.0 0.99))

**Bounded time** — the event's time is unknown but bounded → **`(TimeAtLeast e <term>)` /
`(TimeAtMost e <term>)`** with the same structured terms — **any granularity**: `Year`, `Month`,
`Weekday`, `Hour`. Strict "before / after" drops the boundary point ("before 2000" → at most
**1999**; "after 2015" → at least **2016**; "before March" → at most **february**; "after
October" → at least **november** — decrement/increment the month **name**); "by T" (deadline) →
at most T. `before` / `after` + a **date** is a bound; + an **event/clause** is the `Before`
relation above.

      The bridge was built before 1900.    →  … (Past sk_build_1) (TimeAtMost sk_build_1 (Year 1899))
      The statue was erected after 2015.   →  … (Past sk_erect_1) (TimeAtLeast sk_erect_1 (Year 2016))
      Bob must submit the report by 5 pm.  →  … (Obligated sk_submit_1) (TimeAtMost sk_submit_1 (Hour 17))
      The roof was repaired before March.  →  … (Past sk_repair_1) (TimeAtMost sk_repair_1 (Month february))
      Hand the keys in by Friday.          →  … (Obligated sk_hand_1) (TimeAtMost sk_hand_1 (Weekday friday))

**Intervals** — an eventuality with a stated extent gets **`(Start e <term>)` / `(End e
<term>)`** ("from X to / until Y"; "since X" → `Start` only, usually with `Ongoing`; "until Y" →
`End` only). "**during / while / throughout**" nests one eventuality inside another:
**`(During <inner> <outer>)`**, both reified. A **duration** ("for three hours", "lasted two
days") is a measure — **`(Measure e duration <n> <unit>)`** — converting to canonical **second**
via the seeded lexicon (*Measures & units*); seeded rules also derive a duration from a same-day
`Hour` or `Year` `Start`/`End` pair.

      The market runs from 8 am to 1 pm. →  (Member sk_run_1 run) (Agent sk_run_1 sk_market_1)
                                            (Member sk_market_1 market) (Start sk_run_1 (Hour 8)) (End sk_run_1 (Hour 13))
      Mia has lived in Oslo since 2019.  →  (Member sk_live_1 live) (Agent sk_live_1 mia) (Location sk_live_1 oslo)
                                            (Ongoing sk_live_1) (Start sk_live_1 (Year 2019)) (Name mia "Mia")
      The phone rang during the lecture. →  (Member sk_ring_1 ring) (Agent sk_ring_1 sk_phone_1) (Member sk_phone_1 phone)
                                            (Member sk_lecture_1 lecture) (During sk_ring_1 sk_lecture_1) (Past sk_ring_1)
      Sam drove for six hours.           →  (Member sk_drive_1 drive) (Agent sk_drive_1 sam) (Past sk_drive_1)
                                            (Measure sk_drive_1 duration 6 hour) (Name sam "Sam")

### Time questions

- **When?** → the open `(Time $e $t)` in the event's context — one row per stored granularity or
  deictic. **What year / what day / what time?** → bind **inside** the term: `(Time $e (Year
  $y))`, `(Time $e (Weekday $w))`, `(Time $e (Hour $h))`. Yes/no at a specific time → constants
  in the term.
- **Before / after a date?** → threshold on the bound value — and, like a measure threshold, the
  storage may be **exact** (`Time`) or a **bound** (`TimeAtMost` / `TimeAtLeast`), so emit **both
  branches and union**; only the **matching-direction** bound can confirm ("before" pairs with
  `TimeAtMost`, "after" with `TimeAtLeast`; omit the opposite bound).
- **Month / weekday order** has no number to compare — join the seeded lexicon fact
  (`(MonthNumber $m $n)` / `(WeekdayNumber $w $n)`); the join works on **bounds** the same way:
  `(TimeAtMost $e (Month $m)) (MonthNumber $m $n) (Compute < ($n 5) -> true)`.
- An **hour threshold** follows the measure rule: the stored hour may be **exact** (plain
  number → `Compute`) or **approximate** (distribution → `GreaterThan`, graded) — emit **both
  branches + union**. A threshold **with minutes** ("before 4:30 pm") adds a split: hours
  strictly below, ∪ the boundary hour with minutes below —
  `(Time $e (Hour $h)) (Compute < ($h 16) -> true)` ∪
  `(Time $e (Hour 16)) (Time $e (Minute $m)) (Compute < ($m 30) -> true)`.
  (A boundary-hour event with no stored minutes is genuinely unknown — an open-world miss.)
- **Order of two events?** → `(Before $e1 $e2)` with each event's own anchors (transitivity is
  seeded; fully **dated** events also derive `Before` from their calendar terms via seeded
  strict rules — year, same-year month, same-year-month day). For **undated** events compared
  by month/day, add the two-event **join branch** + union:
  `… (Time $e1 (Month $m1)) (MonthNumber $m1 $n1) (Time $e2 (Month $m2)) (MonthNumber $m2 $n2)
  (Compute < ($n1 $n2) -> true) …`. **How long before?** → bind the `BeforeBy` gap. **How long
  did it take?** → bind `(Measure $e duration $n $u)`; thresholds cross units in canonical
  seconds (*Measures & units*). **Ongoing at T?** → interval containment, two `Compute`s:
  Start ≤ T and End ≥ T.

      When did Omar jog?
        →  (: $prf (And (Member $e jog) (Agent $e $o) (Name $o "Omar") (Time $e $t) (Past $e)) $tv)
      Did the festival open before July?
        →  (: $prf (And (Member $e open) (Patient $e $f) (Member $f festival) (Time $e (Month $m)) (MonthNumber $m $n) (Compute < ($n 7) -> true) (Past $e)) $tv)
      Was the bridge built before 1950?
        →  (: $prf (And (Member $e build) (Patient $e $b) (Member $b bridge) (Time $e (Year $y)) (Compute < ($y 1950) -> true) (Past $e)) $tv)
           (: $prf (And (Member $e build) (Patient $e $b) (Member $b bridge) (TimeAtMost $e (Year $y)) (Compute < ($y 1950) -> true) (Past $e)) $tv)
      Did the fire start before the alarm rang?
        →  (: $prf (And (Member $e1 start) (Patient $e1 $f) (Member $f fire) (Past $e1) (Member $e2 ring) (Agent $e2 $a) (Member $a alarm) (Past $e2) (Before $e1 $e2)) $tv)
      Is the market running at 11 am?
        →  (: $prf (And (Member $e run) (Agent $e $m) (Member $m market) (Start $e (Hour $s)) (Compute <= ($s 11) -> true) (End $e (Hour $n)) (Compute >= ($n 11) -> true)) $tv)
      How long did Sam drive?
        →  (: $prf (And (Member $e drive) (Agent $e $s) (Name $s "Sam") (Measure $e duration $n $u) (Past $e)) $tv)

## Quantifiers, generics & scope (verbal → rules)

A **verbal** generic or universal over a kind becomes a **rule** that gives each instance
its own event, via a **Skolem-function** event term `(sk_<verb> $x)` (distinct per binding;
never a free/unbound variable). Rule strength = the quantity (all `1.0`, generic/most `0.9`,
many `0.7`, few `0.1`); confidence by the dial. A **deontic norm over a kind** ("drivers must
carry a license", "visitors may enter", a prohibition "guests must not smoke") is **not** this
event-rule form — it is a **reified property** on the kind, `(Inheritance <kind> (obligated /
permitted <action>))` (see *Deontic norms & prohibitions over a kind* below), which inherits to
members and can be overridden.

      Birds fly.      →  (: birds_fly (Implication (Premises (Member $x bird))
                            (Conclusions (Member (sk_fly $x) fly) (Agent (sk_fly $x) $x))) (STV 0.9 0.9))
      Birds can fly.  →  (: birds_can_fly (Implication (Premises (Member $x bird))
                            (Conclusions (Member (sk_fly $x) fly) (Agent (sk_fly $x) $x) (Can (sk_fly $x)))) (STV 0.9 0.9))

The **same rule form** distributes a **distributive predicate over a plural or group** — whether an
**explicit universal** ("all the / **all of the** / each (of the) / every (one of the) Ns V", bare
"each / every N V") or a **grouped / counted plural** ("the dogs barked", "several / both dogs
barked" — see *Cardinality*, which keeps the group event + count alongside the rule). A universal
**always distributes** — the "of the" wording does **not** make it a partitive (partitives are
cardinal or non-universal proportional — see *Partitives*); only a **collective** predicate (gather,
meet, assemble) does **not** distribute. Range over the members as the reciprocal rules do (see
*Reciprocals & symmetric relations*): a plural that **names the kind** ("all the students", "each
juror") → `(Member $x <kind>)`; a **specific group** — a collective noun ("every member of the
committee") or a counted/bare plural ("several dogs", "both dogs") → `(PartOf $x <group>)`. Strength
= the quantity (`all` / `each` / `every`, and a plain plural/count = `1.0`), confidence `0.9`:

      All the students passed.      →  (: all_students_passed (Implication (Premises (Member $x student))
                                           (Conclusions (Member (sk_pass $x) pass) (Agent (sk_pass $x) $x)
                                                        (Past (sk_pass $x)))) (STV 1.0 0.9))
      Every member of the committee resigned.
                                    →  (: committee_resigned (Implication (Premises (PartOf $x sk_committee_1))
                                           (Conclusions (Member (sk_resign $x) resign) (Agent (sk_resign $x) $x)
                                                        (Past (sk_resign $x)))) (STV 1.0 0.9))
                                       (Member sk_committee_1 committee)

A **distributive** predicate distributes; a **collective** predicate ("the students gathered",
"the jury deliberated") stays **one** event with the group as agent (see *Coordination &
plurals*). An **explicit universal** ("all the / each / every") is the pure rule above; a
**grouped or counted plural** ("the dogs barked", "several dogs barked", "both dogs barked")
keeps its **group event + count** (for counting and "did any?") **plus** the `(PartOf $x
<group>)` rule alongside — it fires when a member is individuated later (see *Coordination &
plurals*). Query a distributed member like any event — its event class, the roles (a **named**
member bound by `Name`), and status: "Did Ana pass?" (Ana a student) → `(: $prf (And (Name $a
"Ana") (Member $e pass) (Agent $e $a) (Past $e)) $tv)`.

**Negated verbal generic / verbal ¬∀.** "Ns don't V" as a generic habit ("owls don't migrate") =
the **same distributing rule at strength `0.0`** — each member's event then derives at strength 0,
so an arbitrary N does *not* V. "**Not every** N V" ("not every intern replied") is a
**counterexample witness**, parallel to copular "not all" (see **Negation (copular)**): one witness
N at strength 1 plus its event bundle at strength `0.0`.

      Owls don't migrate.       →  (: owls_no_migrate (Implication (Premises (Member $x owl))
                                       (Conclusions (Member (sk_migrate $x) migrate) (Agent (sk_migrate $x) $x))) (STV 0.0 0.9))
      Not every intern replied. →  (: sk_intern_1_i (Member sk_intern_1 intern) (STV 1.0 0.99))
                                   (: sk_intern_1_nr (And (Member sk_reply_1 reply) (Agent sk_reply_1 sk_intern_1) (Past sk_reply_1)) (STV 0.0 0.99))

A clause with **two quantifiers over a relation** — read the natural meaning, not word
order — uses Skolem **functions** for *dependent* existentials, witness **constants** for
*shared* ones, and rule premises for universals:

- **∀∃ (dependent)** "every student read some book" — each its own book:

      (: every_student_read_book (Implication (Premises (Member $x student))
         (Conclusions (Member (sk_read $x) read) (Agent (sk_read $x) $x)
                      (Theme (sk_read $x) (sk_book $x)) (Member (sk_book $x) book))) (STV 1.0 0.9))

- **∃∀ (shared)** "some critic reviewed every film" — one shared critic (a constant):

      (: sk_critic_1_critic (Member sk_critic_1 critic) (STV 1.0 0.99))
      (: that_critic_reviewed (Implication (Premises (Member $y film))
         (Conclusions (Member (sk_review $y) review) (Agent (sk_review $y) sk_critic_1) (Theme (sk_review $y) $y))) (STV 1.0 0.9))

- **∀∀** "every dog chased every cat" — two universal premises:

      (: every_dog_chased_cat (Implication (Premises (Member $x dog) (Member $y cat))
         (Conclusions (Member (sk_chase $x $y) chase) (Agent (sk_chase $x $y) $x) (Patient (sk_chase $x $y) $y))) (STV 1.0 0.9))

- **Three or more** quantifiers generalize this — one premise per universal, and each **dependent**
  existential is a Skolem function of **every** universal that scopes over it (`(sk_<verb> $x $y …)`);
  a shared one stays a constant. "Every teacher gave every student a book" (∀∀∃ — each its own book):

      (: every_teacher_gave_book (Implication (Premises (Member $t teacher) (Member $s student))
         (Conclusions (Member (sk_give $t $s) give) (Agent (sk_give $t $s) $t) (Recipient (sk_give $t $s) $s)
                      (Theme (sk_give $t $s) (sk_book $t $s)) (Member (sk_book $t $s) book))) (STV 1.0 0.9))

- A **number under a universal** ("every student read **three** books") = a per-binding Skolem
  **group** carrying a `Cardinality` — the books vary per student, so the group is a function of `$x`
  ("the **same** three" → one constant group instead, as in ∃∀):

      (: every_student_read_three (Implication (Premises (Member $x student))
         (Conclusions (Member (sk_read $x) read) (Agent (sk_read $x) $x) (Theme (sk_read $x) (sk_books $x))
                      (GroupOf (sk_books $x) book) (Cardinality (sk_books $x) 3))) (STV 1.0 0.9))

  To **query a threshold over such a derived count** ("did Al read more than two books?"), bind the
  member's group through the event and threshold its `Cardinality`:

      Did Al read more than two books? →  (: $prf (And (Name $a "Al") (Member $e read) (Agent $e $a) (Theme $e $g) (GroupOf $g book) (Cardinality $g $n) (Compute > ($n 2) -> true)) $tv)

Cues "the **same** Y" / "a **certain** Y" force the shared (constant) reading; genuine
ambiguity → first quantifier takes wide scope. A relational universal with a **copular**
conclusion mixes the two forms — "everyone who owns a dog is a pet owner":

      (: dog_owner_pet_owner (Implication
         (Premises (Member $e own) (Holder $e $x) (Theme $e $y) (Member $y dog))
         (Conclusions (Member $x pet_owner))) (STV 1.0 0.99))

(**Copular** universals/generics do **not** reify events — "all dogs are mammals", "most
teachers are patient" stay the single `Inheritance` fact from **Categorical statements**.)

**Striking & relational generics** — first judge: does the property hold of *most* individuals of
the kind? The default (a distributing rule, or `Inheritance`, at strength `0.9`) fits only
**majority** generics ("birds fly", "dogs have four legs"). Two cases differ:

- **Relational generic** relating two KINDS ("mosquitoes carry malaria", "bees pollinate flowers",
  "lions have manes", "sharks attack swimmers") → a **kind-level relation** `(<Verb> <kindA>
  <kindB>)` (lemmatized UpperCamelCase head, two kind args), **not** a per-instance rule. It stays
  opaque, so it never distributes — "does *this* mosquito carry malaria?" correctly stays unknown.
  Strength **high** (`0.9`, a true kind characterization); distributing it to all instance-pairs
  would wrongly assert "every mosquito carries malaria".

      Mosquitoes carry malaria.  →  (: m_carry (Carry mosquito malaria) (STV 0.9 0.9))
      Bees pollinate flowers.    →  (: b_poll (Pollinate bee flower) (STV 0.9 0.9))
      Lions have manes.          →  (: l_mane (Have lion mane) (STV 0.9 0.9))

  (An **explicit** universal "every dog chases every cat" stays a ∀∀ rule; a specific past "a dog
  chased a cat" stays an instance event. Only a **bare** relational generic becomes a kind relation.)

- **Striking copular generic** — an "X are ADJ/N" generic true of only a **minority**
  ("politicians are corrupt") → keep `(Inheritance <kind> <prop>)`, but **lower the strength to the
  actual proportion** (striking minority ≈ `0.2`–`0.3`, not `0.9`); the engine distributes it to
  each member at that low strength, so an arbitrary member isn't strongly asserted to have it.

      Politicians are corrupt.   →  (: pol_corrupt (Inheritance politician corrupt) (STV 0.3 0.9))

Rule of thumb: set the strength to what an **arbitrary instance** should inherit — a kind relation
doesn't inherit (stays high), a copular `Inheritance` does (lower it when the property is rare).

**Defeasible generics & exceptions** ("X are/can P, but sub-kind Y isn't/can't"). A general generic
plus a sub-kind exception resolves through the **confidence dial**: state the exception **more
confidently than the general**, and the engine's revision lets the specific override the general for
that sub-kind while ordinary members keep the general value. Emit three `Inheritance` facts — the
**general** `prop` at the empirical generic confidence **0.9**, the **taxonomy** link, and the
**exception** at the **opposite strength** (negation = `0.0`) and the **higher** confidence **0.99**:

      Birds can fly, but penguins can't.
        →  (: bird_canfly   (Inheritance bird (can fly))    (STV 0.9 0.9))
           (: penguin_bird  (Inheritance penguin bird)      (STV 0.99 0.99))
           (: penguin_nofly (Inheritance penguin (can fly)) (STV 0.0 0.99))

A penguin then inherits `(can fly)` ≈ 0 (overridden); other birds stay ≈ 0.9. Reverse polarity is
symmetric — a positive exception to a negative general:

      Mammals don't lay eggs, but the platypus does.
        →  (: mammal_noegg    (Inheritance mammal egg_layer)   (STV 0.0 0.9))
           (: platypus_mammal (Inheritance platypus mammal)    (STV 0.99 0.99))
           (: platypus_egg    (Inheritance platypus egg_layer) (STV 1.0 0.99))

Rules: the exception's **property symbol must match the general's** (`(can fly)`, `egg_layer`); use
the **capability** `(can <verb>)` form when the contrast is ability, a plain **adjective/property**
for copular contrasts ("Mammals are land-dwellers, but whales aren't"). The confidence **gap** is
essential — a **definitional** general (`0.99`) admits no exception (correctly; definitional kinds
have none), so only **empirical** generics (`0.9`) take exceptions. Cues: "but / except / unless /
however / aside from / other than" introducing a sub-kind that lacks or reverses the property. (A
defeasible *relational* generic — opaque kind-relation, **Striking & relational** above — does not
revise this way; keep it to property / capability / categorical generics.)

**Deontic norms & prohibitions over a kind** ("Ns must / may / must-not V"). A deontic norm on a
**kind** is a **reified property** on the kind — `(Inheritance <kind> (obligated <action>))` for an
obligation, `(permitted <action>)` for a permission (lowercase, parallel to `(can <action>)`) —
**not** an event rule. This one form covers plain norms, prohibitions, and (with an added exception
fact) defeasible ones; it inherits to members and can be revised. Decompose the compound action per
**Compound concepts** (`carry_license` → `(Inheritance carry_license carry) (Patient carry_license license)`).

      Drivers must carry a license. →  (: driver_license (Inheritance driver (obligated carry_license)) (STV 1.0 0.99))
      Visitors may enter.           →  (: visitor_enter (Inheritance visitor (permitted enter)) (STV 1.0 0.99))
      Guests must not smoke.        →  (: guest_smoke (Inheritance guest (permitted smoke)) (STV 0.0 0.99))

A **prohibition** ("must not / may not / shall not V") is the **denial of permission** →
`(permitted <action>)` at **strength `0.0`** (not a negated `(obligated …)`). Strength = the norm's
force: a plain norm `1.0` / conf `0.99`; a **defeasible** norm (with a stated exemption) drops the
general to the **empirical `0.9`** so the exception can override it via the confidence dial — the
three-fact pattern:

      Members must pay dues, but lifetime members are exempt.
        →  (: member_dues     (Inheritance member (obligated pay_dues))          (STV 0.9 0.9))
           (: lifetime_member (Inheritance lifetime_member member)               (STV 0.99 0.99))
           (: lifetime_exempt (Inheritance lifetime_member (obligated pay_dues)) (STV 0.0 0.99))

A lifetime member's obligation then ≈ 0 (exempt); a regular member ≈ 0.9 (still obligated). The
confidence **gap** (empirical general `0.9` < exception `0.99`) is the revision lever, so a
defeasible norm's general is `0.9` and a plain norm is `1.0`. Obligation implies permission (seeded
`oblig_perm` fires on the property form too). A **specific one-off** deontic act on an individual
keeps the event form `(Obligated e)` / `(Permitted e)` instead (see *Status predicates*). Exemption
cues: "but / unless / except + exempt / not required / need not / does not have to."

**Conditional properties** ("X is P **when / at / under / if** C" — the property holds only under a
condition). Reify as **`(ConditionalProperty <kind> <property> <condition>)`**; do **not** also
assert the bare `(Inheritance kind property)` (the condition is essential — metals aren't *always*
solid). A seeded rule (`cond_prop`) then gives the property to any member of the kind that is also in
the condition-state, so it connects to a later "the glass is cold" (`(Member glass cold)`):

      Metals are solid at room temperature.  →  (: metal_solid (ConditionalProperty metal solid room_temperature) (STV 0.9 0.9))
                                                 (: rt_genus (Inheritance room_temperature temperature) (STV 0.99 0.99))
      Glass is brittle when cold.            →  (: glass_brittle (ConditionalProperty glass brittle cold) (STV 0.9 0.9))

So "under what condition is metal solid?" = `(ConditionalProperty metal solid $c)` → `room_temperature`,
and a glass known to be cold is derived brittle. Strength = how reliably the property holds under the
condition (generic `0.9`; definitional like "water boils at 100°C" → `0.99`). The condition is an
adjective/state (`cold`, `wet`, `raw`) or a measure / environment (`room_temperature`); decompose a
compound condition per **Compound concepts** (`room_temperature` → `temperature`).

## Reciprocals & symmetric relations

A relation that holds **mutually** — "each other" / "one another", or a predicate symmetric by
meaning ("are friends") — must be encoded so the engine can answer it **either way**.

**"X and Y V each other / one another"**, where the verb is **directed** (not mutual on its own
— "admire", "trust", "help", "blame"): the relation holds **both ways, with the roles swapped**.
For **named, enumerable** participants, emit one directed event per ordered pair, using the
verb's normal roles and swapping the two fillers:

      Alice and Bob admire each other.
        →  (Member sk_admire_1 admire) (Experiencer sk_admire_1 alice) (Stimulus sk_admire_1 bob)
           (Member sk_admire_2 admire) (Experiencer sk_admire_2 bob)   (Stimulus sk_admire_2 alice)
           (Name alice "Alice") (Name bob "Bob")

For an **unnamed group** (you don't have the individuals) emit a **rule** over the members, with
a distinctness guard `(Compute == ($x $y) -> false)` (so nobody pairs with themselves) and a
Skolem-**function** event `(sk_<verb> $x $y)`, one per ordered pair — like the ∀∀ rule above.
**Give the pair the verb's normal roles by the usual test** (see *Thematic roles*): a psych/attitude
verb ("distrust", "envy", "admire") → `Experiencer`/`Stimulus`; a verb whose object is unchanged
("question", "argue with") → `Theme`; only a create/destroy/change verb → `Patient` — never default
to `Agent`/`Patient`. **Range over the predicate the members satisfy**: a plural that **names the kind** ("jurors",
"students") → `(Member $x <kind>)`; a **collective noun** ("committee", "team") whose members'
kind isn't stated → `(PartOf $x <group>)`. Put any tense/status **inside** the `Conclusions` —
never as a free-variable atom outside the rule:

      The jurors distrust one another.
        →  (: jurors_distrust (Implication
              (Premises (Member $x juror) (Member $y juror) (Compute == ($x $y) -> false))
              (Conclusions (Member (sk_distrust $x $y) distrust) (Experiencer (sk_distrust $x $y) $x)
                           (Stimulus (sk_distrust $x $y) $y))) (STV 1.0 0.9))
      The committee members argued with one another.
        →  (: committee_argue (Implication
              (Premises (PartOf $x sk_committee_1) (PartOf $y sk_committee_1) (Compute == ($x $y) -> false))
              (Conclusions (Member (sk_argue $x $y) argue) (Agent (sk_argue $x $y) $x)
                           (Theme (sk_argue $x $y) $y) (Past (sk_argue $x $y)))) (STV 1.0 0.9))
           (Member sk_committee_1 committee)

**Symmetric predicates** — mutual **by meaning** ("are friends / siblings / colleagues", "is
similar / equal / married to", stative "resembles") — assert the relation **once** plus a
**`(Symmetric <Rel>)`** tag (`<Rel>` = the lemmatized predicate, UpperCamelCase). The seeded
`sym_rel` rule derives the reverse direction, so one tag symmetrizes any relation:

      Bob and Alice are friends.  →  (Friend bob alice) (Symmetric Friend) (Name bob "Bob") (Name alice "Alice")
      Carl is similar to Dan.     →  (Similar carl dan) (Symmetric Similar) (Name carl "Carl") (Name dan "Dan")

A symmetric relation over a whole **group** ("the senators are all colleagues") needs **no**
`Symmetric` tag — the group rule already ranges over all ordered distinct pairs, so it yields
both directions; just give it a literal-head conclusion:

      The senators are all colleagues.
        →  (: senators_colleague (Implication
              (Premises (Member $x senator) (Member $y senator) (Compute == ($x $y) -> false))
              (Conclusions (Colleague $x $y))) (STV 1.0 0.9))

**Routing.** An **eventive** symmetric verb (meet / gather / collide) stays **collective** — one
event, multiple `Agent` atoms (see **Coordination & plurals**); only **stative** symmetric
predicates take the relation + `Symmetric` tag. A **collective noun** ("are a couple / a
pair") is a group, not a relation → `(Member sk_couple_1 couple)` + `PartOf` members.

**Querying** matches either direction (the reverse is derived):

      Who is Bob friends with?  →  (: $prf (And (Name $b "Bob") (Friend $b $x)) $tv)
      Does Alice admire Bob?    →  (: $prf (And (Name $a "Alice") (Name $b "Bob") (Member $e admire) (Experiencer $e $a) (Stimulus $e $b)) $tv)

A **group-rule** reciprocal (the unnamed-group form) is queried the same way — each named member
bound by `Name`: "Does juror Ann distrust juror Ben?" → `(: $prf (And (Name $a "Ann") (Name $b "Ben") (Member $e distrust) (Experiencer $e $a) (Stimulus $e $b)) $tv)`.

## Disjunction ("or")

"or" says **at least one** disjunct holds without saying which — reify it with **`(Or <d1> <d2>
…)`**. The engine keeps `(Or …)` **opaque**: it never asserts an individual disjunct (so "Bob or
Alice came" does not make "Bob came" true), which is the faithful reading. Treat every "or" —
including a bare "either … or" — as **inclusive**, *unless* an exclusivity cue fires (see
**Exclusive "or"** below).

**Scope the `(Or …)` as narrowly as possible** — wrap it around only the constituent that varies
and keep the shared/definite parts as ordinary conjuncts of one `(And …)` fact, so those stay
queryable while the Or stays opaque:

      Bob or Alice will come.      (disjoint subject)
        →  (: will_come (And (Member sk_come_1 come) (Or (Agent sk_come_1 bob) (Agent sk_come_1 alice)) (Future sk_come_1)) (STV 1.0 0.99))
           (: bob_name (Name bob "Bob") (STV 1.0 0.99))
           (: alice_name (Name alice "Alice") (STV 1.0 0.99))
      Bob ordered tea or coffee.   (disjoint object)
        →  (: bob_order (And (Member sk_order_1 order) (Agent sk_order_1 bob) (Or (Theme sk_order_1 tea) (Theme sk_order_1 coffee)) (Past sk_order_1)) (STV 1.0 0.99))
           (: bob_name (Name bob "Bob") (STV 1.0 0.99))
      The vase is red or blue.     (disjoint property)
        →  (: vase_color (Or (Member sk_vase_1 red) (Member sk_vase_1 blue)) (STV 1.0 0.99))
           (: vase (Member sk_vase_1 vase) (STV 1.0 0.99))

So "Did someone come?" (`(Member $e come)`) still answers yes, but "Will **Bob** come?"
(`(Agent sk_come_1 bob)`) returns nothing — genuinely unknown. The whole disjunctive clause is
**one `(And …)` fact** (like a negated event); the `(Or …)` and its definite siblings live inside
it, and you do **not** also assert the disjuncts on their own. If a disjunct brings its **own
indefinite entity** ("a salad or a sandwich"), keep that entity's `(Member <witness> <class>)`
**inside** its Or branch (each branch an `(And …)`), so neither object is asserted to exist alone:

      Priya ordered a salad or a sandwich.
        →  (: priya_order (And (Member sk_order_1 order) (Agent sk_order_1 priya)
              (Or (And (Theme sk_order_1 sk_salad_1) (Member sk_salad_1 salad))
                  (And (Theme sk_order_1 sk_sandwich_1) (Member sk_sandwich_1 sandwich))) (Past sk_order_1)) (STV 1.0 0.99))
           (: priya_name (Name priya "Priya") (STV 1.0 0.99))

Use **wide scope** — `(Or <bundleA>
<bundleB>)`, each disjunct a full `(And …)`/atom — only for **independent clauses** that share
nothing: "The server crashed or the network failed" → `(Or (And (Member sk_crash_1 crash) (Agent
sk_crash_1 sk_server_1) (Past sk_crash_1)) (And (Member sk_fail_1 fail) (Agent sk_fail_1
sk_network_1) (Past sk_fail_1)))`.

**Disjunction in a rule's condition → two rules.** An `(Or …)` premise needs *all* its operands,
so split a disjunctive condition into one rule per disjunct (each fires on either):

      A package that is fragile or heavy is flagged.
        →  (: fragile_flagged (Implication (Premises (Member $x package) (Member $x fragile)) (Conclusions (Member $x flagged))) (STV 1.0 0.99))
           (: heavy_flagged   (Implication (Premises (Member $x package) (Member $x heavy))   (Conclusions (Member $x flagged))) (STV 1.0 0.99))

**Disjunctive question → one query line per disjunct** (a single `(Or …)` query would need *all*
disjuncts); any match is the answer:

      Who is faster or stronger than Dan?
        →  (: $prf (And (Name $d "Dan") (More fast $x $d)) $tv)
           (: $prf (And (Name $d "Dan") (More strong $x $d)) $tv)
      Did Bob or Alice call?
        →  (: $prf (And (Name $b "Bob") (Member $e call) (Agent $e $b) (Past $e)) $tv)
           (: $prf (And (Name $a "Alice") (Member $e call) (Agent $e $a) (Past $e)) $tv)

## Exclusive "or" (XOR)

Some "or" is **exclusive** — *exactly one* disjunct holds, **not both**. Default to inclusive
(above); switch to exclusive only on a clear cue: an explicit **"but not both" / "exactly one of
…"**, or an **"either … or"** over two **manifestly contradictory** states of one entity
(open/closed, on/off, awake/asleep, a single location/value). When in doubt, stay inclusive.

Reify exclusivity as **`(Xor <a> <b>)`** — "exactly one of a, b." Like `Or` it is **opaque**
(stores + pattern-queries, never leaks a disjunct); emit it for **every** exclusive-or as the
faithful record.

**When both disjuncts are *atomic*** (one predicate atom each — a property / state / location like
`(Member x open)`, **not** a multi-atom event), also emit the two **strength-0 implications** that
make the exclusivity active — `a → not-b` and `b → not-a`, each an `(Implication …)` at strength
**0.0** (confidence as usual — definitional ≈ 0.99). They let the reasoner **rule out the other**
disjunct once one is confirmed (e.g. later in the passage):

      The door is either open or closed.        (contradictory states → exclusive)
        →  (: sk_door_1_door (Member sk_door_1 door) (STV 1.0 0.99))
           (: door_xor (Xor (Member sk_door_1 open) (Member sk_door_1 closed)) (STV 1.0 0.99))
           (: door_excl_1 (Implication (Premises (Member sk_door_1 open)) (Conclusions (Member sk_door_1 closed))) (STV 0.0 0.99))
           (: door_excl_2 (Implication (Premises (Member sk_door_1 closed)) (Conclusions (Member sk_door_1 open))) (STV 0.0 0.99))

So a later "It is open" (`(Member sk_door_1 open)` at strength 1) makes the reasoner derive
`(Member sk_door_1 closed)` at **strength 0** — the other option is ruled out. With no disjunct yet
confirmed the rules lie dormant (nothing leaks from inside the `Xor`). A confirming state is
**present/unmarked** — "currently / right now it is open" → bare `(Member sk_door_1 open)`, **not**
`(Ongoing …)` — so it matches the rule premise.

**When a disjunct is a *complex / event* proposition** (a multi-atom `(And …)`), emit **only** the
`(Xor …)` label — the strength-0-rule form is unwieldy over events, so the rule-out inference is
dropped there:

      Either Alice will fly to Tokyo or she will take the train, but not both.
        →  (: trip_xor (Xor
              (And (Member sk_fly_1 fly) (Agent sk_fly_1 alice) (Goal sk_fly_1 tokyo) (Future sk_fly_1))
              (And (Member sk_take_1 take) (Agent sk_take_1 alice) (Theme sk_take_1 sk_train_1) (Member sk_train_1 train) (Future sk_take_1))) (STV 1.0 0.99))
           (: alice_name (Name alice "Alice") (STV 1.0 0.99))

A **question** about an exclusive-or matches the `(Xor …)` atom by pattern (bind the unknown side);
if a disjunct was later confirmed, ordinary queries find it and the other reads strength 0.

## Coreference & anaphora

Across a passage, when a later mention refers to an **already-introduced** entity or event,
**reuse the same symbol** — coreference is just symbol reuse, no extra link. First mention
introduces a symbol (witness `sk_<class>_<n>`, event `sk_<verb>_<n>`, or name-derived
`alice`); every later mention of that referent reuses it, so facts from different sentences
attach to one symbol. Resolve each anaphor to the most salient compatible antecedent
(gender/number agreement + recency); if there is genuinely no antecedent, treat it as new.
**A `CONTEXT` block extends the antecedent pool across passages**: its entities (with their
`Name`s and classes) are available antecedents exactly like earlier sentences of the passage —
reuse their symbols, re-emit nothing (see **Input**).

    A man entered. He ordered a beer. The man looked tired.
      →  (Member sk_man_1 man)  (Member sk_enter_1 enter) (Agent sk_enter_1 sk_man_1) (Past sk_enter_1)
         (Member sk_order_1 order) (Agent sk_order_1 sk_man_1) (Theme sk_order_1 sk_beer_1)
         (Member sk_beer_1 beer) (Past sk_order_1)
         (Past (Member sk_man_1 tired))          ; He, The man → sk_man_1 (each atom (STV 1.0 0.99))

- **Named individual** — reuse the name symbol (`alice`) throughout; emit `(Name alice "Alice")` once.
- **Pronoun** (he/she/it/they/him/her/its) — the matching antecedent's symbol.
- **Anaphoric definite** ("the dog", after a dog was introduced) — the antecedent's symbol; a
  first-mention or unique definite ("the sun") → a fresh symbol.
- **Event anaphora** ("it"/"this"/"that" pointing at a clause) — the **event** witness:
  "Bob won. That surprised everyone." → that = `sk_win_1`.
- **Reflexive** ("himself") — the clause's own subject.
- **Mid-discourse naming** ("She named it Rex") — add `(Name <referent> "Rex")` to that referent.
- **Bridging** ("Alice bought a car. The engine was broken") — "the engine" is new but linked
  to the antecedent: `(Member sk_engine_1 engine) (PartOf sk_engine_1 sk_car_1) (Past (Member sk_engine_1 broken))`.
  Bridge the same way when the antecedent and the definite part are in the SAME sentence
  (e.g. two clauses joined by a connective) — the `PartOf` link is still emitted.
- **One-anaphora** ("a red car … a blue one") — "one" = a fresh entity of the antecedent's
  class: `(Member sk_car_2 car) (Member sk_car_2 blue)`.

**Donkey anaphora** — a pronoun bound by a quantifier inside a relative clause maps to that
**rule variable** (put the relative clause in the premises):

    Every farmer who owns a donkey beats it.
      →  (: every_farmer_beats_donkey (Implication
            (Premises (Member $f farmer) (Member $e own) (Holder $e $f) (Theme $e $d) (Member $d donkey))
            (Conclusions (Member (sk_beat $f $d) beat) (Agent (sk_beat $f $d) $f) (Patient (sk_beat $f $d) $d))) (STV 1.0 0.9))   ; it = $d

## Queries — converting a question

A question becomes a **query pattern** — the same content you would assert, with a
`$`-variable in each unknown slot, wrapped as `(: $prf <pattern> $tv)`. Join the conjuncts
of an event/relation with **`And`** on the shared event variable.

- **Yes/no** — no unknown; query the whole proposition (the engine returns its STV).
- **Wh-question** — a `$`-variable where the wh-word asks.
- A **named individual** is bound by its `Name`, not a hard-coded symbol (you don't know the
  KB's symbol): conjoin `(Name $x "…")`.
- The **wh-answer variable is returned bare** — do **not** bind a `(Name $ans …)` for it (its
  symbol already resolves to a `Name` in the KB; binding it drops unnamed answers and adds a
  needless conjunct), and don't restate a class the pattern already fixes.
- A **negative / polarity** question pins the truth value to `(STV 0.0 $conf)`.
- A **compound question** splits by whether its parts **share a referent**. **Shared referent**
  (the same entity — "who is the oldest **and** where do they live?") → **one** query, the shared
  `$`-variable chaining the parts and a `$`-variable per unknown; read every bound `$` as the
  answer. **Independent parts** (no shared variable — "who is the oldest dog, **and** who is the
  youngest cat?") → **one query line each**, like a disjunctive question: a single `(And …)` needs
  *every* part provable at once, so one part with no data drops the **whole** answer. Parts needing
  **different truth-value pins** ("what can X do *and* can't do") also go one line each. (Contrast:
  "**or**" questions are always separate lines — see **Disjunction**.)

      Is Tokyo a city?      →  (: $prf (And (Name $x "Tokyo") (Member $x city)) $tv)
      Was Alice happy?      →  (: $prf (And (Name $x "Alice") (Past (Member $x happy))) $tv)
      What did Bob cook?    →  (: $prf (And (Member $e cook) (Agent $e bob) (Patient $e $what) (Past $e)) $tv)
      What can Bob cook?    →  (: $prf (And (Member $e cook) (Agent $e bob) (Patient $e $what) (Can $e)) $tv)
      Who cooked dinner?    →  (: $prf (And (Member $e cook) (Patient $e dinner) (Agent $e $who) (Past $e)) $tv)
      What does Bob do?     →  (: $prf (And (Member $e $verb) (Agent $e bob)) $tv)
      Can penguins fly?     →  (: $prf (And (Member $e fly) (Agent $e penguin) (Can $e)) $tv)
      Did Bob cook?         →  (: $prf (And (Member $e cook) (Agent $e bob) (Past $e)) $tv)
      Who is the oldest, and where do they live? →  (: $prf (And (Most old $who person) (Member $e live) (Agent $e $who) (Location $e $where)) $tv)
      What did Bob cook, and who ate it?         →  (: $prf (And (Member $c cook) (Agent $c bob) (Patient $c $dish) (Past $c) (Member $et eat) (Agent $et $who) (Patient $et $dish) (Past $et)) $tv)

Build the pattern exactly as the matching statement (same classes, roles, casing, status);
only the unknowns and any named entity become `$`-variables, and the truth value becomes
`$tv` (or `(STV 0.0 $conf)` for a negative question). Output **only** the query — never
assert a `Name` or other fact (a question asks, it does not add knowledge). An **explanation
question** ("why / how / what-for / why-not") is likewise just a query — the focus event pattern
plus a canonical ask-relation conjunct (see **Explanation questions**) — adding nothing to the KB.

## Inter-clause connectives (because / so / although / but / purpose "to")

A **non-temporal connective** stating a relation BETWEEN two clauses — causal ("because", "so",
"as a result", "therefore", "consequently"), purposive ("to" V / "in order to" / "so as to"),
belief-reason ("thought / believed P, **so** …"), concessive ("although", "even though",
"despite"), adversative ("but", "yet") — is captured **surface-faithfully**: reify BOTH clauses
as eventualities (each parsed as usual — classes, roles, tense, negation) and emit **one binary
relation atom whose head is the UpperCamelCase surface connective itself**, with the **main /
matrix clause first and the subordinate clause second**. For a coordinating connective ("so",
"but", "therefore") that is just the surface order; a fronted subordinate ("Because / Although
X, Y") still puts the main clause Y first:

      The latch stuck because the hinge rusted.
        →  (: e_stick (Member sk_stick_1 stick) (STV 1.0 0.99))
           (: e_stick_pat (Patient sk_stick_1 sk_latch_1) (STV 1.0 0.99))
           (: e_latch (Member sk_latch_1 latch) (STV 1.0 0.99))
           (: e_stick_past (Past sk_stick_1) (STV 1.0 0.99))
           (: e_rust (Member sk_rust_1 rust) (STV 1.0 0.99))
           (: e_rust_pat (Patient sk_rust_1 sk_hinge_1) (STV 1.0 0.99))
           (: e_hinge (Member sk_hinge_1 hinge) (STV 1.0 0.99))
           (: e_rust_past (Past sk_rust_1) (STV 1.0 0.99))
           (: conn (Because sk_stick_1 sk_rust_1) (STV 1.0 0.99))

      The hinge rusted, so the latch stuck.
        →  … the same eight event atoms …
           (: conn (So sk_rust_1 sk_stick_1) (STV 1.0 0.99))

      Because the hinge rusted, the latch stuck.
        →  … the same eight event atoms …
           (: conn (Because sk_stick_1 sk_rust_1) (STV 1.0 0.99))   (fronting changes nothing — main clause still first)

- **Do NOT normalize the connective** to a canonical relation — there is no closed causal
  lexicon. The surface word IS the data (a multiword connective CamelCase-joins: "as a result"
  → `AsAResult`, "in order to" → `InOrderTo`, "even though" → `EvenThough`); merging
  "because" / "so" / "led to" into one causal notion is downstream work, not the translator's.
  The connective atom is `(STV 1.0 0.99)` (a definitional record of the stated connective).
  Emit it ONLY for an explicit connective — bare juxtaposition of clauses or sentences states
  no relation and gets **no** connective atom.
- **Temporal connectives get NO connective atom** — "after / before / when / while / until /
  as soon as" locate eventualities in time and keep their canonical forms from the time
  sections (`Before`, `During`, …). A connective atom is emitted only when the connective
  states cause / purpose / concession / contrast.
- A **purpose infinitive** ties the main action to the purpose eventuality (main action first):
  "The clerk knelt to check the drain." → `(To sk_kneel_1 sk_check_1)` (head `To`; "in order
  to" → `InOrderTo`). **Not** "**too** / **enough** ADJ **to** V" — a degree-governed
  infinitive is the **capability** form (see **Comparatives & degree**), not a purpose.
- **Belief-reason**: after an attitude clause, the antecedent of "so" is the attitude
  eventuality itself — "Joel thought the tram would be crowded, so he cycled." →
  `(So sk_think_1 sk_cycle_1)` (the belief content attaches to the attitude event by its role,
  e.g. `Stimulus`).
- **Causation-flavored VERBS are ordinary verbs** — "caused", "triggered", "prevented … from",
  "stopped … from", "made" parse as verbal events with their usual roles, never as relation
  heads; an embedded complement eventuality is reified and attached to the matrix verb by
  `Theme`. In "V-ed NP from V-ing", the NP is the embedded event's participant only — give it
  its role INSIDE the embedded event, not on the matrix verb. A **non-finite embedded
  eventuality** ("from slipping", "to check the drain") carries **no** tense/status atom of
  its own unless its own grammar marks one ("would V" → `Future`) — whether it actually
  occurred is not stated, so assert or deny nothing about that.
- A **copular STATE that is a connective-atom endpoint** is reified as a state witness
  `sk_<prop>_<n>` with `(Member sk_<prop>_<n> <prop>)`, its subject attached by `Experiencer`
  (reserve `Holder` for possession — see **Thematic roles**), **and ALSO emit the flat
  `(Member <subj> <prop>)`** so a plain "is X P?" still resolves (both forms coexist; reify
  only when the state is such an endpoint, otherwise just the flat copular form):
  "The wallpaper peeled because it was damp." →
  `(Because sk_peel_1 sk_damp_1)` with `(Member sk_damp_1 damp) (Experiencer sk_damp_1
  sk_wallpaper_1)` + flat `(Member sk_wallpaper_1 damp)`.

## Explanation questions (why / how / what-for / why-not)

An explanation question asks for the stated reason of a **focus** event. The stored connective
head is a surface word the question cannot name — but seeded engine rules derive a canonical
**`(ReasonFor <reason> <event>)`** from every reason-bearing head (because / since / so / as a
result / therefore / consequently / thus), and **`(PurposeOf <goal> <event>)`** from the
purpose heads (`To`, `InOrderTo`, `SoAsTo`), with `PurposeOf` chaining into `ReasonFor`. Build
the focus event pattern exactly per **Queries** (classes, roles, tense) and conjoin the asked
relation — these two canonical heads appear ONLY in queries and seeded rules, never in
translated statements:

- "**why** …?" / "**what made** …?" / "**how come** …?" → conjoin `(ReasonFor $r <focus>)` —
  one line; causes, purposes, and belief-reasons all bind through the bridge.
- "**what** … **for**?" / "in order to do what?" → the purpose only: `(PurposeOf $g <focus>)`.
- "**how** did … happen?" (mechanism) → the chain into the focus, binding the intermediate:
  `… (ReasonFor $mid <focus>) (ReasonFor $c $mid)` in the same `And`.
- "**why didn't** …?" → the focus is the negated event: build the focus pattern with the
  `(STV 0.0 $conf)` pin (per **Queries**) and conjoin `(ReasonFor $r <focus>)`; it can bind
  only when the text actually stated the non-occurrence and a reason for it.

Nothing about the question is ever asserted.

      Why did the latch stick?
        →  (: $prf (And (Member $e stick) (Patient $e $l) (Member $l latch) (Past $e) (ReasonFor $r $e)) $tv)

      What did the clerk kneel for?
        →  (: $prf (And (Member $e kneel) (Agent $e $c) (Member $c clerk) (Past $e) (PurposeOf $g $e)) $tv)
